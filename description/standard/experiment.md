# 实验验证规范

> **适用范围：** 本规范位于 `description/standard/`，适用于 `experiment/` 下所有 Agent、模型、提示词、检索、索引、性能和质量验证实验。

> **目标：** 让每次实验都可复现、可审计、可比较；实验结论必须能追溯到同一运行目录中的原始产物。

---

## 1. 实验的三层结构

每个实验由方案、运行产物和人工分析组成，三者职责不得混淆。

```text
experiment/<实验名称>/
├── README.md                 # 实验方案与复现入口
├── run.py                    # 可执行实验
└── output/<UTC 时间>/
    ├── manifest.json          # 输入、版本、配置和运行环境
    ├── result.json            # 结构化结果与计算后的指标
    ├── <原始产物>             # 响应、指标快照、日志、样本清单等
    └── analysis.md            # 人工分析，可追加，不改写历史
```

- **方案**回答“要验证什么、如何验证、与什么比较”。
- **运行产物**记录机器直接产生的事实，不在运行完成后改写。
- **分析**回答“观察到什么、能得出什么、还有什么未被验证”。

---

## 2. 实验方案 README

每个 `experiment/<实验名称>/README.md` 必须包含以下内容：

| 小节 | 必填内容 |
| --- | --- |
| 用途与假设 | 要验证的设计决策，以及成立和不成立时各自意味着什么。 |
| 实验设计 | 输入样本、对照组、变量、固定条件和运行顺序。 |
| 指标与判定 | 指标定义、计算口径、通过/失败/无结论标准。 |
| 运行方式 | 可直接复制的命令、前置服务与所需环境变量。 |
| 产物说明 | 每个输出文件的职责及原始产物的位置。 |
| 局限性 | 尚未覆盖的样本、并发、时间、成本或正确性边界。 |

实验名使用小写 kebab-case；实验输出目录使用 UTC 时间戳，例如 `20260825T044706.552897Z`。

---

## 3. 运行产物契约

### 3.1 `manifest.json`

`manifest.json` 记录能够重现实验的静态事实，至少包含：

- 实验名称、开始时间、代码或提示词版本。
- 输入样本的稳定标识，例如文件路径、文档 SHA-256、样本集版本。
- 模型、服务地址、关键生成参数和并发设置。
- 页面渲染、分批、检索或索引等会影响结果的配置。
- 对照组和变量的取值。

不得写入 API key、密码、完整敏感合同内容或不必要的个人信息。

---

### 3.2 `result.json`

`result.json` 保存经过程序计算的结构化结果和指标。每项指标必须注明或可由方案推导其单位、样本数和计算方式。

性能实验至少区分：

| 指标 | 定义 |
| --- | --- |
| 端到端耗时 | 从实验入口到结果返回，包含准备、网络和模型调用。 |
| 模型调用耗时 | 单独计时的模型请求；仅该指标可用于比较缓存前后的模型加速。 |
| 资源或缓存指标 | 例如 prompt token、缓存命中 token、GPU 使用率或检索候选数。 |

不得把包含额外准备步骤的端到端耗时与纯模型调用耗时混作同一加速比。

---

### 3.3 原始产物

按实验需要保留原始响应、指标快照、日志、错误信息、采样清单或校验报告。原始产物一经生成不得人工修改；若重新运行，必须创建新的 UTC 输出目录。

长模型输出不应复制进 `analysis.md`，分析只链接产物并引用必要的短片段、计数或比例。

---

## 4. `analysis.md` 报告格式

每个运行目录只维护一个 `analysis.md`。首次创建使用实验名称作为一级标题；每次分析以带时区的二级标题追加，禁止覆盖或改写历史记录。

> **视觉分割要求：** 实验报告中的相邻标题之间必须使用单独一行 `---` 分隔。一级标题与首个二级标题之间、每个二级记录之间，以及同一记录的各主要三级章节之间均适用此规则。

每次分析至少采用以下模板：

```markdown
# <实验名称>分析

---

## <YYYY-MM-DDTHH:MM:SSZ>

---

### 分析范围

说明本次分析覆盖的运行目录、样本、比较对象和排除项。

---

### 结论摘要

先给出通过、失败或无结论；说明结论适用范围和主要限制。

---

### 实验设计与指标口径

列出对照组、固定条件、变量、样本数、指标公式和单位。

---

### 关键证据

- [原始产物名称](relative-path)：可直接观察的事实。

---

### 原因判断

明确哪些是基于证据的推断，以及尚不能证明的替代解释。

---

### 风险与局限

说明样本覆盖、并发、缓存淘汰、随机性、服务负载或人工标注等限制。

---

### 建议措施

列出可执行的后续实验、实现调整或上线前验收项。

---

### 验证状态

使用 `通过`、`失败` 或 `无结论`，并说明下一步验证条件。
```

简单实验可以合并“实验设计与指标口径”和“风险与局限”，但不得省略分析范围、结论摘要、关键证据、原因判断、建议措施和验证状态。

---

## 5. 证据与结论规则

- **可观察事实**必须链接同目录中的 `manifest.json`、`result.json`、原始响应、指标或校验产物。
- **推断**必须使用“基于上述证据可以推断”等明确措辞，并说明尚未排除的解释。
- **结论范围**必须写明模型、提示词版本、样本、并发和时间条件；禁止把单样本结论扩展为生产结论。
- **比较实验**必须在每个被比较的输出目录中都追加分析，并互相使用相对链接关联。
- **性能指标**只说明性能，不得替代字段准确率、证据可追溯性或专家审核的质量结论。

---

## 6. 运行前与分析前检查

运行前确认：

- [ ] 假设、对照组和判定标准已写入实验 README。
- [ ] 输入样本和模型/提示词/配置版本可稳定识别。
- [ ] 输出目录为新的 UTC 时间戳，避免覆盖既有产物。
- [ ] 已识别可能污染结果的缓存、并发、随机种子和服务负载。

分析前确认：

- [ ] `manifest.json`、`result.json` 和必要原始产物完整存在。
- [ ] 指标单位、样本数和比较口径一致。
- [ ] 报告标题之间已使用 `---` 分隔。
- [ ] 所有结论均已链接原始证据，并区分事实与推断。
- [ ] 已写明验证状态、局限性和下一步措施。
