# 提示词工程规范

> **适用范围：** 本规范位于 `description/standard/`，适用于 `app.agent` 中调用本地 MLLM 的 Core、Attribute、Field Discovery、Clause、Abstract 及后续审核辅助节点。
>
> **核心要求：** 多节点提示词必须优先形成尽可能长且字节稳定的公共前缀；模型输出必须遵循“证据在前、推理摘要在中、最终决定在后”。

---

## 1. 规范职责

本文件负责规定提示词的分层、公共前缀、证据推理协议、结构化输出和验证方式。字段含义、取值范围与输出 Schema 应由字段定义或机器可读契约负责，提示词只引用并解释当前任务所需内容，不复制第二份完整定义。

提示词必须具备版本标识。版本只在提示内容或输出协议发生实质变化时更新；时间戳、请求编号、追踪信息等运行时数据不得写入版本，也不得进入公共前缀。

---

## 2. 最大公共前缀

vLLM 的自动前缀缓存按已处理 token 及其前缀识别可复用的 KV Cache 块。只有从请求开头连续相同的内容才能命中，因此内容相同但顺序、空格、换行、角色边界或序列化方式不同，也可能提前终止前缀复用。技术原理见 [vLLM Automatic Prefix Caching](https://docs.vllm.ai/en/stable/design/prefix_caching/)。

> **排列原则：** 复用范围越广、变化频率越低的内容越靠前；节点专属、合同专属和单次重试内容依次后移。

### 2.1 请求分层

所有 MLLM 节点使用同一个提示词编排器，按以下顺序构造请求：

```text
公共系统前缀
  1. 角色、事实来源与安全边界
  2. 全局术语和证据协议
  3. 推理摘要与最终决定协议
  4. 通用结构化输出规则

合同公共前缀
  5. PDF 页面图像，按原始页序稳定排列

节点专属后缀
  6. 运行模式与节点任务
  7. 字段定义、任务规则和输出 Schema
  8. 仅该节点需要的上游结果

重试后缀
  9. 校验错误、冲突说明和修复要求
```

同一份合同的 Core、Attribute、Clause 和 Abstract 请求应复用完全相同的“公共系统前缀 + 页面图像”序列，再追加节点专属指令。这样既能跨合同复用稳定系统前缀，也能让同一合同的并行节点继续复用页面图像之前及页面图像本身的前缀。

Attribute 需要 Core 上下文时，Core 结果只能追加在合同公共前缀之后。Clause 与 Abstract 不消费 Core 或 Attribute 结果，不得为了统一模板而注入无关上游产物。

### 2.2 稳定性要求

- 公共前缀由单一模板和单一渲染函数生成，禁止各节点复制后独立修改。
- 固定使用相同的消息角色、消息数量、内容块顺序、标点、空格和换行。
- 字典与字段列表使用确定性排序；相同输入必须产生完全相同的序列化结果。
- PDF 页面按原始页码升序传入；不得在不同节点使用不同文件编码、缩放结果或图像顺序。
- 时间戳、`document_id`、运行 ID、节点名、重试次数和追踪字段放在节点后缀；若模型任务不需要，则完全不传入。
- 节点差异只出现在公共前缀之后，不通过在前缀中插值空值或条件段落实现。
- 提示词版本变化会自然形成新的缓存前缀；同一运行批次不得混用多个无必要差异的版本。

### 2.3 重试与调度

校验失败后的重试应保留原请求前缀不变，只在末尾追加最小修复信息。不要将上次完整输出、异常堆栈或动态时间写回公共规则之前。

共享 MLLM 并发配额的节点宜在同一合同处理窗口内集中调度，使仍有复用价值的缓存块更可能保留。前缀缓存只减少相同前缀的预填充计算，不减少输出 token 的生成成本，不能替代合理的并发控制、上下文裁剪和输出长度限制。

### 2.4 工具模板位置

函数工具定义属于模型实际 token 序列的一部分。默认 Qwen3.6 模板把工具放在 system 内容之前，会使不同工具请求在 PDF 之前分叉；项目统一使用[vLLM 自定义聊天模板](../capability/vllm-chat-template.md)控制工具位置，不允许节点复制或临时改写模板。

- 并行任务共享完全相同工具时，使用 `before_task`，顺序为“公共前缀 → 工具 → 当前任务变量 → 短期历史”。
- 工具根据当前定义动态生成时，使用 `after_task`，顺序为“公共前缀 → 当前任务变量 → 工具 → 短期历史”。
- `tool_placement` 由程序按节点契约传递，不得从用户文本、PDF 内容或模型输出推断。
- 公共前缀与任务变量必须使用明确消息边界，使模板能够稳定定位最后一个真实 user 任务。
- 同一工具会话的工具块必须固定在初始任务和 assistant/tool 历史之间；除状态机明确改变可用工具外，不得重排工具列表。

## 3. 证据、推理与决定

> **输出顺序：** 先列可定位的原始证据，再给出从证据到规则的简洁推理摘要，最后输出决定。最终决定不得引入前两部分没有依据的新事实。

本项目使用 CoT 作为推理纪律：要求模型充分比较证据、规则、冲突与不确定性，但不要求输出逐 token 的隐式思维链、草稿或冗长自言自语。对外返回的是可审计的推理摘要，而不是隐藏推理过程的逐步转录。

严格 JSON 提取继续显式设置 `enable_thinking=false`。该参数用于禁止模型额外输出思考通道，避免破坏 Schema；它不取消“证据 → 推理摘要 → 决定”的结构化推理要求。

### 3.1 证据在前

每条关键判断先提供证据。证据至少包含页码和可核对的原文片段；视觉信息无法用文本充分表达时，可增加区域、表格行列、印章或版式说明。

- 只引用 PDF 中可以直接观察的内容，不把推断写成原文。
- 原文片段保持简短且足以支持判断，不复制整页内容。
- 同时存在支持、反对或冲突证据时全部列出，不选择性隐藏。
- 找不到证据时返回空证据集合，并在最终决定中使用 `not_found` 或约定的不确定状态。
- 规范化值与原始证据分离；金额、日期和主体名称的转换不能改写引用原文。

### 3.2 推理摘要在中

推理摘要只解释证据如何满足或不满足当前字段定义与业务规则，至少覆盖：

1. 使用了哪些证据及对应哪条规则。
2. 是否存在冲突、歧义、缺页、遮挡或识别不确定性。
3. 为什么选择当前规范值或不作判断。

摘要应简洁、结论导向且可由证据复核。禁止输出无助于审核的探索过程、重复改写提示词、虚构的工具调用或无法验证的心理活动。

### 3.3 最终决定在后

最终决定只汇总已经论证的结果，并遵循机器 Schema：

- `found`：存在充分证据，返回原始值、规范值和必要状态。
- `not_found`：已检查输入但没有支持证据，不使用常识或默认值补全。
- `uncertain`：证据冲突、质量不足或规则无法唯一匹配；保留冲突说明供专家审核。

若具体 Schema 没有 `uncertain` 状态，应按该契约规定的失败或审核队列协议处理，提示词不得自行创造新枚举。

---

## 4. 结构化输出模板

输出 Schema 的字段顺序应体现证据优先。以下仅展示组织方式，不替代任务的正式机器契约：

```yaml
evidence:
  - page: 1
    quote: "可直接核对的短原文"
    location: "可选的视觉位置"
reasoning_summary:
  rule_applied: "证据与字段规则的对应关系"
  conflicts: []
  uncertainty: null
decision:
  status: found
  raw_value: "原文值"
  normalized_value: "规范值"
```

如果既有契约使用 `reason` 字段，则该字段承载 `reasoning_summary` 的职责，必须放在证据之后、决定之前，并保持简洁。任何情况下都不得新增 `chain_of_thought`、`scratchpad` 或类似字段。

---

## 5. 节点提示词要求

| 节点 | 公共规则之外必须明确的内容 | 禁止事项 |
| --- | --- | --- |
| Core | 固定字段定义、规范化规则、Core 上下文输出 | 创造目录外字段 |
| Attribute | 当前模式的固定 Attribute 定义、可用 Core 上下文 | 从 Core 结果替代 PDF 取证 |
| Field Discovery | 已覆盖字段、候选准入和排除规则 | 将候选直接写成正式字段 |
| Clause | 视觉与法律效果边界、原始顺序 | 混入主体清单或签署资料 |
| Abstract | 固定摘要结构与可引用事实范围 | 引入合同外知识或法律意见 |

节点提示词只包含完成本节点所需的上游数据。公共规则、字段定义和任务输入必须以结构化块呈现，避免把大量机器契约压缩成难以校验的自然语言段落。

---

## 6. 验证与观测

新增或修改提示词时至少完成以下检查：

- 对公共前缀做快照测试，保证不同节点的共享部分逐字节一致。
- 相同输入重复渲染两次，结果必须完全一致。
- 检查第一个节点差异出现的位置，确保所有可共享内容均位于该位置之前。
- 校验输出严格满足 Schema，且字段顺序为证据、推理摘要、决定。
- 使用无证据、证据冲突、跨页证据和 OCR 噪声样例验证失败边界。
- 记录公共前缀 token 数、总输入 token 数、缓存命中 token 数或命中比例，以及首 token 延迟。
- 比较提示词版本时同时记录模型版本、生成参数、页面渲染参数和字段目录版本。

缓存指标只能用于判断性能，不得作为抽取正确性的证据。提示词上线前仍需使用有人工结论的合同样本验证字段准确性、证据可追溯性和失败行为。
