# 模型全局并发额度

> **用途：** 限制单 worker 中所有合同、业务分支和后台任务发往模型服务的在途请求总数，避免节点局部并发相互叠加。

---

## 共享范围与配置

`app.infrastructure.model_concurrency` 为应用事件循环维护两个独立的共享配额池。当前部署限定单 worker、单事件循环，因此是该后端进程的全局额度；不是多个进程、容器或服务器之间的分布式配额。

| 配置 | 默认值 | 共享范围 |
| --- | --- | --- |
| `VLLM_MLLM_MAX_CONCURRENT_REQUESTS` | 20 | 全部 `MLLMClient` 普通生成、工具调用及媒体缓存重填请求。 |
| `VLLM_EMBEDDING_MAX_CONCURRENT_REQUESTS` | 10 | 全部 `EmbeddingClient` 文本批量向量化与页面多模态向量化请求。 |

同一类别不按用户、合同、节点、模型名或 URL 再拆额度。会话记忆加工同样复用统一客户端，因此与合同提取共享配额；不同类别互不占用。一个包含多条文本的 Embedding HTTP 批次占一个额度，而非每条文本各占一个。

节点现有局部信号量继续保留，控制单节点任务展开；最终发送必须同时满足全局额度。调整上述配置需要重启应用。启动时固定额度，客户端也支持在离线脚本中首次调用时初始化；同一事件循环内收到不同额度配置时显式报错，不创建第二个池或重置正在使用的配额。

---

## 请求生命周期

统一入口为 `get_model_request_limiter(kind, maximum)`，调用方通过 `async with` 获取和归还 `asyncio.BoundedSemaphore` 额度，不在 Agent 节点中直接获取全局配额。

1. MLLM 先执行媒体 UUID 协调，等待同页首次填充时不占全局配额。
2. 每次实际 HTTP 尝试取得额度后，才将进程内 PNG 引用编码为 Base64 并构造请求。文本与多模态 Embedding 在同一个共享池中执行。
3. 请求返回或抛出异常后归还额度。缓存失效重填重新获取额度，不在已持有额度时递归申请。
4. 排队期间取消，不调用远端服务；发送期间取消、连接失败、超时、HTTP 错误或序列化异常均自动释放额度。媒体首次填充失败继续按原协调器规则唤醒跟随者。

页面向量化的消息构造器同时接受 `PNGImage` 与原有 PNG data URL，正式工作流传入引用，避免全局排队期间提前持有 Base64。模型看到的图片、提示词、工具和向量化指令保持不变，详见 [vLLM 多模态媒体引用](vllm-media-reference.md)。

额度由事件循环持有，关闭单个模型客户端不会重置共享池；新事件循环使用新池，避免复用旧循环的等待状态。

---

## 时间与容量边界

- SDK 请求超时从进入 SDK 调用后生效，不包含全局配额排队时间；本次未增加队列等待超时或排队容量限制。
- 现有客户端耗时指标包含配额等待及媒体协调时间，不等于纯模型执行时间；服务端推理耗时仍读取独立指标，详见 [推理观测](inference-observability.md)。
- 当前客户端采用非流式模型请求，额度覆盖请求到响应接收的生命周期；后续若增加模型流式接口，必须持有额度直至流关闭，不能仅限制建连。
- 本限制约束客户端在途请求数量，不限制 token、显存或服务端内部任务数量；客户端取消后远端是否立即停止计算取决于模型服务。
- 本次不实现合同执行队列、上传文件上限、驻留 PNG 总字节预算或优先级调度。等待任务依然占用内存，不能把全局并发控制等同于内存上限。
- 多 worker 或多个完整服务副本各自拥有额度，不能直接用单进程配置推断服务器上的合计负载。
