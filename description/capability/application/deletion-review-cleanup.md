# 已完成删除审核申请定时清理

`DeletionReviewCleanupService` 定时清理已处理完成的删除审核快照和 `deletion_reviews` 行，保留最小幂等凭据。参照[入库审核清理](ingestion-review-cleanup.md)组织生命周期，但删除审核区只保存正式 PDF 引用，没有独立临时 PDF，因此本服务不删除文件、正式元数据、ES 或 Neo4j。

---

## 完成条件与保留期

同时满足以下条件才进入清理：

- 已保存审核反馈消息 ID 和本地 `review_processed_at`。
- 审核批准且 `deletion_status=succeeded`，或审核拒绝且已完成标志协调。
- 本地处理完成时间早于或等于“当前时间减保留时长”。

批准时，正式删除执行成功与完成时间在同一个审核库事务中保存。拒绝时，由申请服务在恢复 `can_delete=true` 后保存完成时间；恢复失败不开始计时。原合同已不存在、已重新入库或已有后续申请时，旧拒绝不再修改当前标志，可以记录本地处理完成。

每个处理完成时间只首次写入，不因重复反馈或扫描刷新。未送审、待审核、批准但删除未完成/失败、拒绝但标志尚未协调的申请不会清理。计时不采用申请创建时间、远端审核时间或 updated_at。

默认完成后保留 7 天，启动后立即扫描，随后每小时一轮，每轮最多 100 份。保留期表示允许清理，不保证截止时刻立刻完成。

---

## 事务、凭据与重放

每条清理与提交申请、处理反馈共享同一合同锁，并在独立 SQLite 写事务中重新核验状态及保留期，然后：

1. 在 `processed_deletion_review_receipts` 保存 submission_id、原请求 ID、反馈 ID、规范化反馈内容 SHA-256、本地处理完成时间和清理时间。
2. 删除 `deletion_reviews` 整行，合同身份快照、双方备注、人员、passport 和执行记录随行移除。
3. 同一事务提交；任何写入或删除失败全部回滚，下轮重试。

凭据不保存合同 ID、名称、摘要、PDF 引用、人员、备注或原始反馈。反馈时间统一为 UTC 后计算哈希，同一时刻的不同 ISO 时区表示仍被视为同值。重放必须同时匹配请求 ID、反馈 ID 和内容哈希；匹配返回 `ProcessedDeletionReviewReceipt`，不重新修改标志或执行删除，冲突仍报错。

清理与反馈读取交错时，申请服务会重新检查凭据；不能把已经清理的申请当作未知反馈直接忽略。相同 submission_id 禁止再次保存，旧请求/反馈 ID 不能绑定新申请。查询列表不包含凭据，清理后详情返回404，不从凭据恢复历史快照。

目前尚未接入中间件删除反馈消费和 ack。本服务先提供内部幂等契约，后续消费者应对匹配的已处理凭据跳过业务操作、直接确认消息。由于未约定重投最大期限，最小凭据暂不自动过期。

---

## 失败与生命周期

单条清理失败保留记录，只记录申请 ID 与异常类型，继续其他候选。全局候选读取失败下轮重试，不阻断服务启动。同实例扫描串行，数据库事务和状态复核防止重复生成凭据；当前仍要求单 worker 部署。

服务关闭时停止新领取并等待当前清理事务结束，再停止正式删除执行器、释放存储依赖。清理服务不调用 PDF 删除方法，不遍历文件目录，不接触引用地址，即使审核拒绝的合同仍在正式库中也只清理审核记录。

记录被清理后释放审核表中 document_id 的申请唯一性。批准记录在保留期内仍占用该唯一性；若同一 PDF 再次入库，其再次删除申请需等待旧批准记录清理。

## 配置、装配与查询

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `DELETION_REVIEW_RETENTION_SECONDS` | `604800` | 本地处理完成后的保留秒数，有限正数。 |
| `DELETION_REVIEW_CLEANUP_INTERVAL_SECONDS` | `3600` | 每轮结束后的等待秒数，有限正数。 |
| `DELETION_REVIEW_CLEANUP_BATCH_SIZE` | `100` | 每轮最多处理的申请数，正整数。 |

`.env`、`.env.example` 和 `Settings` 均已提供配置。`app/bootstrap.py` 将实例存入 `app.state.deletion_review_cleanup_service`，正式删除执行器启动后启动清理，退出时先关闭清理。`start()` 创建后台任务，`scan_once()` 返回本轮清理数量，`close()` 停止并等待当前操作。

存储方法为 `list_cleanup_candidates(cutoff, limit)` 和 `cleanup_completed(submission_id, cutoff)`，由申请服务协调合同锁。初始化幂等补齐完成字段、凭据表和清理索引；旧批准成功记录仅使用已有本地 deletion_completed_at 补齐完成时间，旧拒绝记录等待标志协调后计时。

[删除审核查询 API](../../api/deletion-review.md)提供详情的 `cleanup.review_processed_at`、`cleanup.eligible_at` 和服务器时间。前端只在 eligible_at 非空时计算倒计时，清理与详情查询可能交错。
