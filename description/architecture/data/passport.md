# 合同通行证集合

`passport` 表示一份合同关联的完整通行证数组。同一合同可关联多个通行证，同一通行证也可关联多份合同；合同自身仍以 document_id 标识，不以通行证作为唯一键。

---

## 数据与传输契约

| 场景 | 契约 |
| --- | --- |
| 入库审核反馈 | passport 必填，为字符串数组；兼容旧单字符串，空字符串转为空数组。缺失或 null 不作为拒绝处理，不入库、不 ack。 |
| 批准与拒绝 | 非空数组按批准处理，全部通行证随同一份合同入库；空数组沿用未签发即拒绝的业务规则，不创建正式合同。 |
| 合同与审核查询 API | 正式合同列表的 passport、入库详情的 review.passport、删除详情的 passport 均返回数组；尚未收到反馈或历史未绑定值保留 null。 |
| 删除送审 | 至少一个通行证，使用重复 passport 表单字段提交全部值；不拼接逗号，不将整个数组序列化成单个表单字符串，不上传文件。 |
| 通行证查合同 | 工具仍接收单个完整通行证，精确匹配集合成员，返回所有 ready 合同；同合同重复出现同一值不重复返回。 |

数组中的每项必须为非空白字符串；不允许数字、null、对象或嵌套数组。保留原值、顺序和重复项，不裁剪首尾空白，不补全、不拆解通行证内容。模型查询工具同样按提供的原值精确查询。

```json
{"passport": ["PASS-001", "PASS-002"]}
```

一条审核反馈仍对应一个 message_id 和一次 ack，不按通行证数量拆成多条反馈或多份合同。前端删除申请的 note 必填规则不变。

---

## SQLite 存储与升级

正式库 contracts、入库审核库 ingestion_reviews、删除审核库 deletion_reviews 的 passport 列仍为 TEXT，但非空值保存为 JSON 数组文本；NULL 表示尚无绑定信息，JSON 空数组表示已收到未签发反馈。程序读取后使用不可变元组，HTTP JSON 输出为数组。

各库初始化调用 `app/infrastructure/passport_storage.py` 进行一次性迁移，以 `PRAGMA user_version` 标记存储格式：版本0为历史标量，版本1起为 JSON 数组。转换与版本号在同一数据库事务中提交，转换失败不提交版本号；重复初始化不再次包装。旧单字符串转单元素数组，旧空字符串转空数组，NULL 不变。历史形似 JSON 的字符串仍视为一个原始通行证，禁止通过猜测字符串内容决定格式。

更新后重启后端即可在初始化阶段迁移，升级前应停写并备份正式库和两个审核库及其文件。保持库文件与版本号成套备份，不手动重置 user_version。无法解码的已迁移存储明确失败，不回退猜测为单字符串。

通行证查询使用参数化 `json_each` 成员匹配，保留 ready 过滤、入库时间倒序及合同 ID 升序。原 `contracts_passport` 普通索引保持兼容，但单标量索引不用于 JSON 成员查询；当前未新增倒排关联表。

## 幂等与身份保护

正式入库、删除快照、删除许可恢复及正式删除校验完整数组，不能仅取第一个通行证。已绑定的数组不可被另一数组覆盖、截断或清空；同一 document_id 和完整数组的入库重放复用原 ready 记录，不重算向量或覆盖入库时间。数组顺序与重复项属于冻结内容，变化视为冲突。

入库反馈重投先规范为数组，再与已保存反馈比较。历史已清理记录只有旧反馈哈希时，对单值数组或空数组同时校验等价的历史标量哈希，继续核对请求 ID 和反馈 ID；不允许通过修改其他字段或通行证绕过冲突检查。消息 offset 与 ack 粒度保持不变。

## 实现与验证

- `app/core/passport.py`：严格规范化，兼容旧标量，保留数组全部内容。
- `app/infrastructure/passport_storage.py`：JSON 编码、解码及格式迁移。
- 中间件适配、审核区 Schema、正式元数据、入库服务、删除快照和通行证工具复用同一契约。
- `tests/test_passport_collections.py`：临时 SQLite/PDF 与模拟 HTTP，覆盖多个值、重复项、首尾空白、旧标量、空数组、非法数据、迁移重复执行、历史反馈哈希、完整入库重放及删除表单多值。
