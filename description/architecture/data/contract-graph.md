# 合同关联图存储契约

本文定义 Neo4j 中合同节点与无向关联边的身份、属性和生命周期。节点同步和[关系创建接口](../../api/contract.md#创建合同关联)已实现；[独立删除接口](../../api/contract.md#删除合同关联)已实现，[一跳关系查询](../../api/contract.md#获取合同一跳关系列表)已实现。

部署和异步客户端见 [Neo4j 部署与开发连接](../../capability/infrastructure/neo4j-development.md)，跨存储状态与恢复见[合同正式入库](../../capability/application/contract-ingestion.md)。

---

## 合同节点

节点使用 `Contract` 标签，以完整 `document_id`（64 位小写 SHA-256）作为唯一业务身份。名称、摘要等元数据保存在 SQLite，节点不重复维护。

正式入库时幂等创建节点，图节点成功后才发布合同为 `ready`；启动时为历史正式合同补建节点。删除合同时清理该节点及全部关联边，不删除相邻合同节点。

---

## 关系边

两份合同以 `RELATED_TO` 建立业务上的无向关联。两端合同 ID 由边所连接的节点确定，不使用 Neo4j 内部 ID 作为外部业务标识。

| 属性 | 类型 | 来源与含义 |
| --- | --- | --- |
| `relation_id` | 字符串（UUID） | 后端创建时生成的关系唯一 ID，用于定位和删除关系。 |
| `description` | 字符串 | 用户填写，去除首尾空白后 1 至 10000 字符，可说明两份文件的角色及关联原因。 |
| `created_at` | 带时区日期时间 | 后端生成的 UTC 创建时间；对外序列化为 ISO 8601。 |
| `created_by` | 字符串 | 从当前登录身份取得的用户名称，作为创建人快照保存。 |

此外保存内部属性 `pair_key`，值为按字典序排序的完整 ID 以冒号拼接，用于数据库级无向端点去重，不接受客户端指定、不在响应中公开。`pair_key` 与 `relation_id` 分别具有唯一约束。

客户端只提交两端合同 ID 与描述，不指定关系 ID、操作人或创建时间。当前系统所有已登录用户具有统一操作资格；不引入管理员等级。

关系只保存创建信息，不保存 `updated_at`、`updated_by`。字段名统一使用 `description`，不另设含义重复的 `note`。描述中的角色应明确对应具体合同，避免依赖展示顺序使用“前者”“后者”。

示意属性如下，时间及 ID 仅为说明格式：

```yaml
relation_id: "c514f63b-4526-4672-aa96-d960e5b1a006"
description: "设备采购合同为主合同，交付补充协议调整其交付期限。"
created_at: "2026-09-18T08:00:00Z"
created_by: "amy"
```

## 创建、删除与重建

1. 创建前检查两份合同均存在且为 `ready`，禁止合同关联自身。
2. 每对合同只保留一条无向边，`A—B` 与 `B—A` 视为同一关系。按合同 ID 排序固定存储方向，查询时忽略方向；重复创建不能覆盖已有属性。
3. **关系创建后不可修改。** 不提供修改描述、替换端点或更新创建信息的操作，也不提供关系修改接口。
4. 关系有误时先删除原边，再创建新边。新边生成新的 `relation_id`、`created_at` 和 `created_by`，不沿用原边身份及创建信息。
5. 删除为物理删除；删除任一端合同也会清理关联边。删除并重建是两个操作，重建失败时原边仍保持已删除，不隐式恢复。

新增关系时，在两端合同就绪校验后调用 Embedding 服务编码描述，再进入图事务。描述、向量和编码信息在同一条 `ON CREATE SET` 中写入；向量生成或校验失败时不创建关系。已有边仍返回冲突，不能覆盖描述或向量。

## 关系描述向量

新建关系额外保存以下内部属性，不改变创建及一跳查询的 HTTP 返回字段：

| 属性 | 含义 |
| --- | --- |
| `description_embedding` | 描述的 L2 归一化浮点向量。 |
| `embedding_model` | 本次使用的 Embedding 模型名称。 |
| `embedding_version` | 编码指令版本，当前为 `contract-relation-description-v1`。 |
| `embedding_dimensions` | 本次向量维度。 |

编码由 `app/service/contract_relation_embedding.py` 提供，复用 `EmbeddingClient`、全局 Embedding 并发配额和现有 `VLLM_EMBEDDING_*` 配置，不另设模型或连接配置。使用现有文本编码的 ChatML 输入形式：system 放关系描述编码指令，user 放经请求校验的描述原文；不加入合同哈希、作者或创建时间。指令保留合同角色、关联原因、条件、否定和不确定性，不补造事实。

响应必须匹配配置模型、一个向量和配置维度；布尔值、非有限数值、零向量与非法范数均拒绝。向量统一 L2 归一化，图存储入口再次检查数值和编码信息。连接在成功、失败或取消时关闭，模型调用不置于 Neo4j 事务回调中，驱动重试不会重新编码。

此阶段只实现新增关系编码及持久化，未创建向量索引、全文索引或检索接口。历史关系不会自动回填，仍能正常查看和删除；后续建立向量检索时必须处理历史缺失值及模型/维度兼容性。数据库启动不调用 Embedding，更换模型不会自动重算既有向量。

验证：关系 API 与编码/图写入的 15 项单元测试通过；未执行真实 Embedding 与 Neo4j 联调，也未修改已有业务关系。

创建人和创建时间不是完整操作审计：删除后不保留该边历史，当前契约不包含独立删除日志或版本记录。

## 实现边界

已实现 `ContractGraphStore` 的节点唯一约束、幂等创建和节点及关联边删除，并接入合同入库、删除及启动恢复。

已实现关系属性写入、无向边并发去重及创建时与合同删除的锁协调。`ContractRelationService` 复用入库服务的 `lock_documents()`，按排序后的两端 ID 获取锁并在状态校验及图事务期间持有；当前仍限定单 worker。`ContractGraphStore.create_relation()` 在图事务中匹配节点和关系，只对新建边写入属性，已有关系返回冲突。

UUID 和 UTC 时间在事务回调之外生成，驱动重试时复用，避免把本次已提交的写入识别为其他关系。独立 HTTP 重试重新生成 UUID，若关系已存在则返回 `409`，不静默覆盖。

独立删除按关系 UUID 执行单个图事务，保留两端节点和其他关系；使用实际删除计数区分成功与不存在。旧 ID 的重试不会影响删除后重建的新边。一跳关系查询已实现，多跳遍历尚未实现；不提供修改接口。已实现的请求响应、错误码及示例以[创建合同关联](../../api/contract.md#创建合同关联)为准。

## 一跳关系读取

`ContractGraphStore.list_relations(document_id)` 忽略边方向，固定匹配一条 `RELATED_TO` 边，返回对方合同 ID、关系 UUID、描述、创建时间及创建人。按创建时间降序、关系 UUID 升序排序，图节点缺失与无关联分开反馈。

`ContractRelationService.list_relations()` 校验起点合同为 `ready`，并过滤对方合同不存在或非 `ready` 的条目，保留查询顺序。对外模型为 `ContractNeighborResponse`；完整接口见[获取合同一跳关系列表](../../api/contract.md#获取合同一跳关系列表)。
