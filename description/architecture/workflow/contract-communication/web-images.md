# 网页图片阅读

> **用途：** 通过现有 `open_web_page` 让精炼模型和主模型实际查看网页中的相关图片。实现参考 `knowledge-accumulation-be` 的候选提取、图片选择、原生展示与任务生命周期，并适配本项目的工具执行及页面折叠契约。

本能力不新增模型工具、SSE 事件或图片资源接口。正文精炼沿用本项目现有方式；本次不迁入对方的全文原文与摘要语义分流。

---

## 执行与模型输入

首次读取按 `fetch_html → extract_text → load_images → refine_content → finalize` 执行。正文区候选图片下载后，精炼模型接收网页文字、访问限制、关注重点、真实 `image_url` 图像块，以及图片编号、图注和附近正文。只有图片可用时也可以继续；图片下载失败但文字可用时仍返回文字及图片未核实提示。

`WebPageRefinement` 按 `evidence/reasoning/type/result/selected_images` 返回，提示词版本为 `web-page-refinement-v6`。`selected_images` 只能选择本次实际提供的整数编号；拒绝布尔值、字符串、重复编号、虚构编号、超过保留数，以及 `no_content` 携带图片。输入有图时必须显式提交选择列表，无相关图使用空列表。

最多三次输出纠错，只追加最小反馈；失败输出和原生思考不会回显给模型，成功后清理临时失败轨迹。完整原始响应留在查看器既有私有审计中，不写入用户正文。图片内容和网页文字同属外部资料，不能改变系统指令、工具权限或输出契约。

精炼成功后，`open_web_page` 第1页同时返回文字与图片的轻量引用，主模型通过页面解析器得到真实PNG内容块。翻到后续文字页不会重复打开图片；显式 `page=1` 可重新查看并生成新的展示身份。图像和文字共同计入实际模型输入预算，沿用 `VLLM_MLLM_PAGE_DISPLAY_ROUNDS` 自动折叠。

## 提取与下载边界

`subgraph/web_page/image.py` 优先从 article/main 提取 img，缺失时回退页面；支持 src、常见懒加载属性和 srcset，保留实际图注、alt 与附近正文。过滤导航、明显图标/广告、标注极小尺寸的图片与重复URL；下载后按标准化图片内容再次去重。

静态JPEG、PNG、WebP和GIF可读取；动态图、SVG、CSS背景图、需要JavaScript生成或登录后才能访问的图片不在本次支持范围。源图最多1600万像素、最短边至少48像素；按EXIF方向处理，透明区域置白，最长边缩至1280像素并编码PNG。数量、分辨率和读取时限有限，不能声称已经阅读网页所有图像，也不能依据图注猜测未提供图片的细节。

图片阶段共享15秒总时限，最多3次重定向。每次请求仅允许不含账号密码的HTTP/HTTPS地址及常用端口。DNS结果必须全部为公网地址，连接固定已校验IP，HTTPS保留原域名Host、SNI与证书校验；每次重定向重新验证地址。图片请求不携带应用身份、环境代理或跨跳Cookie。

`app/infrastructure/public_dns.py` 沿用正常系统DNS。只有系统结果全部处于 `198.18.0.0/15` Fake-IP网段时，才向固定 `https://1.1.1.1/dns-query` 发送图片域名作公开A记录补解析，以兼容现有代理环境；5秒超时、64KiB响应上限计入图片阶段总时限，不跟随重定向。补解析结果仍须为公网IP；混入内网/回环、直接使用Fake-IP字面地址或补解析失败时拒绝读取，不修改系统DNS或其他服务配置。

## 缓存、授权与释放

纯文字快照继续使用会话级 `(source_id, focus)` LRU；包含图片的快照增加任务作用域键，由 `WebPageViewer.task_scope()` 绑定当前任务。`CommunicationWorkflowService` 通过 `CommunicationFileTools.web_page_task_scope()` 围绕整个正式生成持有作用域，完成、取消、失败、替代退出和停机取消均会释放本轮图片快照。会话关闭和LRU也可提前释放。

没有有效任务作用域时，不允许建立带图片快照；不同任务不能读取彼此的图片。作用域结束后迟到请求不能重新写入缓存。下一任务如需看图，使用有效来源标识和focus重新读取；纯文字快照可以继续驻留。

图片已被LRU释放时，解析器抛出 `ToolPageUnavailable`，页面展示层给出明确的不可读提示并继续处理其他资料，不使用空图或伪造图像。篡改签名、非法编号、跨任务引用和权限失效仍是明确错误，不降级为图片内容。

PNG仅驻留任务内存，不写入附件目录、工作区、数据库、SSE或公开历史。`WebPageResult.images` 和 `WebImage.png` 排除常规序列化；工具回执仅有来源、定位、数量及限制。模型已经生成的文字观察和轻量引用仍按正常轨迹保存；释放图片不删除这些文字。

A2A可以注入同一网页工具与 `viewer.resolve_page`，但必须由受信调用方用 `with viewer.task_scope():` 包围 `run_a2a_task(...)`。A2A本身不会自动装配网页来源、凭据或资源池，且不产生SSE。

## 配置与依赖

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `COMMUNICATION_WEB_IMAGE_MAX_CANDIDATES` | 6 | 每页最多读取并交给精炼模型的候选图片数 |
| `COMMUNICATION_WEB_IMAGE_MAX_SELECTED` | 3 | 每页最多保留给主模型的图片数 |
| `COMMUNICATION_WEB_IMAGE_MAX_BYTES` | 4194304 | 单图下载及标准化PNG字节上限 |

三项均为正整数，无额外固定数量上限；默认值仅在未配置时使用。数量增加仍受格式、像素、总下载时限与模型上下文预算约束。配置变更需重启服务；现有私有 `.env` 未改写。

`requirements.txt` 显式声明Pillow和lxml，HTTP、Trafilatura、LangGraph及多模态MLLM客户端复用既有依赖。模型必须支持原生图片输入；本次未调整模型地址、服务端模板或前端。

## 验证

`tests/test_web_images.py` 的14项隔离测试覆盖候选提取、PNG标准化、来源与内容去重、IP固定、重定向/Cookie隔离、Fake-IP补解析、严格选图与纠错、纯图页面、图片失败后正文保留、首页/翻页/重看、任务结束与迟到结果、LRU不可读提示及签名校验。

其中共享Core集成测试通过实际工具注册、FIFO和页面展示路径，确认下一次主模型请求包含选中图像的真实PNG内容块。与模式划分和原生thinking回归合计29项通过；网络和模型均为替身，未进行真实公网或模型联调。
