# 原生思考 FIFO 窗口

> **状态：** 已实现独立窗口、配置、原位置回注、SQLite 落盘与重载。不会自动恢复中断的模型请求，也不改变未完成任务的恢复能力。

---

## 用途与收录边界

思考窗口保留最近 K 份完整原生思考，提供短期分析连续性，同时避免思考无限累加。它独立于任务轨迹 FIFO，不伪造 think 工具调用，不写入工作区，也不替换工具调用或执行结果。

当前收录范围为：主助手开启 thinking，模型完整返回，恰好一个合法工具调用且动作最终被接受。保存 reasoning 或 reasoning_content 的原始字段和完整文本。原始字段出现在失败调用、协议错误、纯思考无工具响应或截断输出中时，仅保留既有审计/纠错处理，不进入此窗口。接受纯思考轮属于另一项协议变更，本次未实现。

任务结束不清空窗口。窗口可以同时包含多个任务的思考，但始终绑定各自的原任务和原响应；不会把上一个任务的思考当作当前任务的新思考。

---

## 位置、驱逐与上下文注入

每条 ReasoningEntry 保存单调递增的 position、稳定 task_id、原始 call_id、原生思考字段及 token 数。position 不因驱逐重排；task_id 和 call_id 是实际定位锚点。任务展示序号可能因摘要插入而变化，user 系统提示也可能改变消息下标，因此不使用这些可变下标定位。

窗口按先入先出驱逐完整条目，不截断推理文本；超过 K 或 token 总上限时持续移除最早条目。单份思考超过整个预算时，该份也不保留。新响应没有思考时不追加条目；失败和截断不替换已有条目。普通工具交互始终按原生命周期保留，不随思考驱逐而删除。

注入分两种展示形式：

| 位置 | 回注方式 |
| --- | --- |
| 当前活动任务 | 在匹配 call_id 的原始 assistant 消息中恢复 reasoning/reasoning_content，工具调用与反馈位置不变。 |
| 已结束任务 | 原任务已按可读块展示，因此将思考展示在对应工具调用前；finish_task 的思考位于最终输出前。明确标注这是当时分析，不等于已核实事实。 |

只对本次上下文中实际存在的原任务与原响应注入。任务已被摘要覆盖、未加载或不存在时，跳过相应条目，不复活被压缩任务、不挪到最新任务。重新打开会话时加载窗口，随后上下文组装自动按同样的规则定位，无需把思考再复制进任务记录。

完整请求计数和 FIFO 用量包含本轮实际注入的思考。摘要输入使用原有干净交互消息，排除原生思考字段和含思考的派生渲染文本；窗口不自动进入摘要或长期事实记忆。

---

## 存储与恢复

`conversation_reasoning_windows` 为每个会话保存一份完整窗口 JSON，包含 next_position 和保留条目。写入校验会话所有权，通过期望位置检测旧副本冲突，相同回执可重复确认。会话删除时通过外键级联删除，普通驱逐保留磁盘窗口。

主循环先确认工具交互已被接受，再计数并保存思考。历史服务在共享锁内校验活动任务与真实调用位置，通过独立短事务先落盘、后替换驻留窗口。思考不等待任务结束才保存，不进入公开 SSE、普通任务 payload 或公开历史响应。

思考窗口和普通任务备份是不同事务：窗口落盘不等于原任务已经完成备份。若进程在活动任务尚未备份时退出，窗口可能存在而原轨迹未恢复，此时不注入找不到位置的思考。当前服务不自动续跑未完成任务；原任务轨迹恢复后才能按锚点注入。本次保证已持久化任务与窗口重新加载后的原位置恢复，不声称提供整轮任务的崩溃检查点。

保存失败会停止本轮正常继续，不重新执行已经成功的工具。与工具执行事实及任务终态的处理边界沿用[主循环](agent-runtime.md)。

## 配置与接口

```dotenv
VLLM_MLLM_REASONING_WINDOW_ROUNDS=3
VLLM_MLLM_REASONING_WINDOW_MAX_TOKENS=16384
```

对应 MLLMSettings.reasoning_window_rounds 与 reasoning_window_max_tokens，均为非负整数。任一为 0 不保留新思考；主循环回注也按当前限制筛选，调小配置会立即缩小注入范围，下次窗口写入更新落盘内容。关闭 thinking 时主循环不注入、不追加思考，不自动删除已有磁盘记录。配置不自动开启原生思考。

| 组件 | 接口职责 |
| --- | --- |
| `app/schema/reasoning_window.py` | 窗口校验、完整条目驱逐、绝对位置与原生消息回注。 |
| `SQLiteCommunicationStore` | read_reasoning_window / save_reasoning_window，授权读写与位置冲突校验。 |
| `ConversationHistoryService` | 驻留窗口、重载、已接受调用与思考的绑定、落盘提交。 |
| `CommunicationWorkflowService` | 活动任务和用户校验、将窗口快照传给上下文组装。 |
| `context.py` 与任务渲染器 | 当前原生字段及历史原位置的派生注入，不改写任务 payload。 |

## 验证与限制

`tests/test_reasoning_window.py` 覆盖 K 轮 FIFO、绝对序号不重排、token 上限、0 禁用、消息按任务与调用定位、输入不变、所有权、写入冲突、会话删除级联、真实主循环采集，以及 SQLite 重新打开后历史思考回到工具调用和最终输出前。

回归使用模拟模型与计数器，不代表已完成当前 vLLM 聊天模板的真实保留效果测试，也不证明保留思考提高回答质量。原生字段进入实际消息后由服务端模板消费，需另做真实对照验证。原始私有审计仍按原策略管理，窗口驱逐不清除审计。
