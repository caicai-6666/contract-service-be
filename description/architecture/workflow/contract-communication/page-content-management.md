# 页面内容折叠与资源建模

> **状态：** 已确认的设计指导；普通/可折叠返回契约与注册校验已实现，主循环可配置轮数的展示与折叠已实现；文件查看已注册并接入正式循环及会话资源释放；表格查询仍未实现。

本文是 Agent Core 大容量页面内容管理的设计依据。工具接入沿用[统一工具注册](tool-execution.md#统一注册契约)，模型输入由[上下文装配](context-assembly.md)和[主助手生成循环](agent-runtime.md)组织；FIFO 的任务级压缩仍遵循[FIFO 管理](fifo-management.md)。

---

## 1. 目标与基本原则

多页表格、文件图片及整页长文本可能在单个活动任务中持续累积。仅在任务结束后清理，无法控制长任务执行期间的上下文占用，因此采用“页面默认展示5轮后折叠”的机制。

**展示生命周期按模型生成轮次管理，会话资源按会话驻留管理，公共合同模型可由全局缓存管理。** 页面折叠改变模型看到的内容，不等于删除原始文件，也不等于销毁工具内部的资源模型。全局共享仅针对文件模型，翻页位置仍按会话隔离。

三个概念需要区分：

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 原始资源 | 文件或查询所依赖的数据来源 | 已持久化的 PDF、业务数据库 |
| 资源模型 | 工具为访问和分页建立的可复用对象 | 文件解析对象、一次查询得到的临时表格 |
| 页面展示 | 一次工具返回中准备供模型阅读的内容 | 文件第3页图片、表格第51–100行 |

资源模型不是模型生成的分析结论。模型提取出的事实、必要证据、工作区内容及最终答复，继续按既有机制保留。

## 2. 职责分工

| 模块 | 负责内容 | 职责边界 |
| --- | --- | --- |
| 具体工具 | 建立文件或表格资源模型；处理指定页、翻页、行范围等请求；返回带类型的页面结果；资源缺失时判断能否重建 | 不自行修改任务轨迹、不控制页面折叠时机 |
| 外层上下文管理器 | 识别页面结果；注入本轮完整内容；次数耗尽后仅保留占位；按实际展示状态计算 token；释放展示引用 | 不理解 PDF 解析、表格分页或查询重建逻辑 |
| 会话资源管理器 | 持有当前会话的资源模型和缓存；支持跨任务访问；在会话驱逐或删除时协调释放 | 不决定本轮展示哪些页面，不替工具重跑查询 |

工具返回类型由程序实现确定，不由模型填写。外层根据返回类型识别普通结果与页面结果，统一应用生命周期规则；不让每个工具分别维护展示期限或折叠策略。

资源模型的具体结构由工具定义，会话资源管理器负责统一持有和释放。永久文件的恢复能力、临时查询结果的不可恢复性，也由具体工具判断。

公共合同文件模型采用应用持有的全局缓存时，不属于会话资源管理器的释放范围；会话只持有独立查看器及阅读位置。文件查看的来源与缓存接口见下文[文件查看器](#文件查看器)。

## 3. 页面结果与展示规则

页面结果已作为可折叠结果的轻量引用建模，具体字段与状态见[工具返回的内容分类](tool-execution.md#工具返回的内容分类)。下表说明其职责：

| 信息 | 用途 |
| --- | --- |
| 资源标识 | 指向文件或临时表格等资源 |
| 页面定位 | 页码、行范围等重新访问所需信息 |
| 展示标识 | 标记本次返回，区别于资源身份；再次打开同页必须获得新的展示机会 |
| 展示内容 | 文本、表格数据或图片，由上下文层转换为实际模型消息 |
| 简短说明与来源 | 支持生成折叠占位及后续核对 |

一次工具返回可以同时包含需要保留的普通结果说明和多个页面。各页面共同进入后续模型请求，默认可见5轮；同一返回中的页面共享本批剩余次数，不同返回分别计数。

展示流程如下：

```text
工具成功返回页面结果
→ 登记本次展示及资源引用
→ 下一次模型请求注入完整页面，并按实际内容计数
→ 模型生成完整返回，本批剩余次数减1
→ 次数大于0时继续展示；为0时后续上下文用占位替换页面，释放本次展示引用
```

网络失败、取消或输出截断不算成功消费。任务仍可继续恢复时，保留展示机会；若任务已经终止，则清理尚未消费的展示引用，资源模型仍按会话生命周期管理。次数耗尽的页面不因后续纠错自动重新展示，需要再次调用相关工具打开。

页面从工具返回后的第一次展示开始计数，默认前5轮保持可见，第5轮完整返回后折叠，第6轮生成不再展示。即使本轮选择输出进度、工具参数错误或工具执行失败，也会减少一次。交互提示词 v15 已说明临时页面的阅读与信息提取规则，重要信息及时写入工作区，需要核对时重新打开，不依靠模糊记忆补全。

保留轮数由环境变量配置，模型不能自行设置展示期限或固定页面。跨页比较通过一次共同打开必要页面完成。工具仍须限制单次页数或行数，避免一次展示本身超过上下文容量。

占位示意：

```text
文件：采购合同.pdf
引用：file_001，第3页
[本页图片已隐藏；需要时可通过文件查看工具重新打开。]

表格：设备明细
引用：table_001，第2页，第51–100行
[本页表格内容已隐藏；可尝试引用此表格重新查看，资源可用性由工具检查。]
```

占位由程序生成，不伪装成文件原文或模型总结。历史引用不保证资源当前可用，也不应在仅发生折叠时宣称资源已释放。

## 4. 资源有效期与缺失处理

会话专属资源模型在当前会话驻留期间有效。一个任务完成、取消、被替代或失败，不释放整个会话的资源模型；后续任务可以继续使用有效引用。任务终止时只清理本任务的临时展示引用及相关在途使用。公共合同模型可跨会话共享，随全局缓存失效、淘汰或应用关闭释放，不随单个会话驱逐释放。

会话驱逐或删除时统一释放资源模型、缓存和临时文件，协调在途使用的取消或结束，避免关闭仍被使用的对象。进程重启后不保证临时模型和缓存仍然存在；不会因为历史轨迹保留了引用，就承诺可以恢复全部资源。

| 资源类别 | 驻留期间 | 资源模型缺失后 |
| --- | --- | --- |
| 临时查询结果、临时表格 | 保存本次结果，支持跨任务分页访问 | 返回不可用提示，要求重新执行查询；不自动重跑原查询 |
| 已永久存储的文件 | 缓存解析对象和可复用页面 | 校验来源存在、访问权限及必要版本信息后，按需重新建模并打开目标页 |

临时表格不因本机制永久保存。重新查询产生新的资源标识，不将新结果悄悄绑定到旧引用，避免数据变化后“第2页”已经表示另一批记录。

持久化文件使用稳定文件标识，必要时绑定版本或内容指纹。不能恢复到同一来源时，应返回明确反馈，不静默打开其他文件或新版本；文件删除和权限变化不能被缓存绕过。会话资源释放不删除由原有存储机制管理的永久文件。

不可恢复资源的反馈意图为：“该临时资源当前不可用，请重新执行查询以建立资源。”程序只能确定资源缺失时，不猜测是会话驱逐、进程重启还是从未建模。具体错误码及反馈 Schema 留待实现时定义。

## 5. 与轨迹、计数及审计的关系

页面管理是任务级 FIFO 压缩之外的机制。折叠不驱逐任务、不生成摘要、不修改工作区，也不改变工具已经成功执行的事实。

FIFO 保留成功的工具调用、来源定位、页面引用及占位；完整大内容通过临时展示层注入。常规私有审计和请求日志同样避免长期持有图片、整页表格或其 Base64 副本，否则上下文层释放引用后，其他副本仍会占用内存。折叠不得破坏原生 function calling 的调用与反馈配对，也不撤销现有错误轨迹清理规则。

计数必须使用本轮实际展示状态：页面可见时计完整内容和视觉用量，折叠后只计占位与保留信息。正式实现需同时对齐完整请求检查与 FIFO 容量管理，避免计数器仍计算已经隐藏的页面，或遗漏本轮注入的内容。

资源模型占用的内存与模型上下文 token 是两种不同额度。页面折叠只保证减少模型输入；若渲染缓存仍持有同一图片，其内存并不会立即释放。实际释放由展示引用和资源缓存的持有关系决定，会话驱逐时应完成兜底清理。

## 6. 后续实现与验收边界

返回类型已接入统一工具注册与结果校验。主循环通过 page_resolver 接入可信资源解析器后支持 foldable；未提供解析器仍在装配时阻断此类工具。PageDisplayWindow 按调用标识定位回执，在其后注入临时页面；模型完整返回后减少一次，耗尽才折叠；退出生成循环时清空待展示引用。会话文件资源已由 CommunicationFileTools 持有并接入驱逐和删除回调。

文件引用、分页与文件数 LRU 容量策略已实现；表格接口和总内存预算尚未实现。完整生成但工具协议非法时仍减少一次，后续纠错不重置计数；尚有次数则继续展示，截断不减少。当前主循环发生网络错误或任务终止时退出并清理窗口，不承诺跨重启恢复未消费展示。

验收至少覆盖：

- 完整页面默认展示5轮，第6轮起隐藏；不同批次分别计数；重新打开同页获得新展示机会。
- 请求失败或截断不消耗展示机会；任务终止清理展示引用而不销毁会话资源。
- 同一驻留会话跨任务引用有效；会话驱逐、删除和在途取消不会泄漏资源或错误关闭对象。
- 临时表格缺失时明确反馈且不自动重查；持久化文件缺失模型时按权限及来源版本重建。
- 页面折叠前后计数与实际请求一致；FIFO 和常规审计不保留完整大内容副本。
- 工具执行状态、调用配对、已提取结论和工作区不因折叠而改变。


提示词接入：`agent-core-interaction-v15` 已条件式解释上述模型可见规则，包含隐藏页面核对、临时表格失效和已有证据充分三类示例；不包含内部驱逐流程，文件资源模型管理与展示折叠已接入，临时表格资源仍待实现。版本与主助手装配见[主助手提示词设计](agent-core.md#可折叠内容的提示词认知)。

## 文件查看器

`agent_core/tool/file_viewer.py` 统一实现 FileModel、FileModelCache、两类磁盘读取函数与 FileViewer。两个文件查看工具已通过正式注册表进入主循环，会话资源装配与驱逐回调已接入。

构造：`FileViewer(conversation_id, resolve_file=resolver, read_file=reader, cache=cache, config=None)`。每个查看器服务一个驻留会话、一个来源；附件池会话独有，合同池全局共享。各查看器独立保存按完整文件版本键索引的游标，以及本查看器发出的轻量页面引用。共享同一池的查看器应采用相同渲染配置。

| 接口 | 当前行为 |
| --- | --- |
| `await open(file_id)` | 确认来源，缺失时读取并建模，返回 FileDescriptor；不推进游标，失败抛 FileViewError。 |
| `await view(file_id, page_number=None)` | 明确页码或下一页；首次默认第1页。成功返回 FIFOExecutionResult + foldable 引用，失败返回 ordinary 错误反馈。 |
| `await resolve_page(reference)` | 直接作为 PageDisplayWindow 的解析函数；核对本查看器引用与文件版本，必要时重建，返回实际 image_url 内容块。 |
| `await aclose()` | 清除游标和展示引用并拒绝新请求；不关闭宿主拥有的文件池。 |

成功取页且返回结果构造完成后才更新游标；错误或取消不提交新的游标和引用。缓存驱逐不会删除阅读位置，同版本文件重新建模后可继续下一页；版本变化后的新查看从第1页开始。省略页码且已到末页时返回 end_of_file，提示没有下一页并可指定页码重看；显式指定越界页返回 page_out_of_range，提示实际页数和合法范围。零、负数或非整数仍为 invalid_arguments（注册入口也会按参数Schema拒绝）。两类失败均不推进游标，不循环或猜测页码。open 不保证资源始终驻留，后续每次访问均可恢复缓存缺失。

读取、解析与缓存操作在线程中执行，同一查看器的异步操作顺序执行。缓存新增 acquire_or_load，将缓存未命中加载、接管与借用原子衔接，避免新入池模型在取页前再次被驱逐；初版通过池共用锁串行缺失加载，不能在加载函数中反向等待查看器。入池失败会释放未接管的新模型。取消异步等待不终止底层线程，线程仍会正确归还借用或关闭未接管模型；模型若已入池，由宿主文件池继续管理。

来源定位函数必须每次检查当前存在性、访问范围和版本，缓存命中也调用它。读取与页面获取后再次确认描述一致；哈希形式的 revision 还会核对实际读取内容，其他版本号的内容一致性由可信来源保证。查看器不把已缓存模型或旧引用当作访问授权。

成功回执只包含 file_id、文件名、当前页、总页数和简短提示。content 使用 `FoldableToolContent`，其中 `ToolPageReference` 包含稳定资源标识、每次新生成的 display_id、page:N 定位及 image 类型；不保存 PNG 或 Base64。解析器拒绝跨查看器引用、篡改引用及文件版本变化，不自动替换为新版同页；在模型池驱逐后可重新读取原版本。展示次数与折叠仍由外层窗口管理，解析页面不移动阅读位置或生成新展示机会。

错误反馈采用 `status=failed` 和普通内容，tool_result 包含 code 与可执行的 error 文本，不回显路径、密钥或底层堆栈。代码包括 invalid_arguments、file_not_found、file_unavailable、invalid_pdf、page_out_of_range、end_of_file、file_changed、cache_busy、read_failed、viewer_closed 等；未知错误使用 view_failed。页面解析阶段错误抛 FileViewError，由现有上下文展示流程停止本次构造，不能伪造空图片或重新执行原工具动作。

离线测试已覆盖真实 PDF 取页、共享池独立游标、驱逐后翻页和延迟解析重建、五轮展示及折叠、重新打开的新展示标识、引用篡改/跨查看器拒绝、撤权/删除/版本变化、页码错误、无效 PDF、池容量不足及关闭后的共享池保留。

## 文件查看参数模型

两个工具分别使用独立 Pydantic 模型，均定义在 `tool/file_viewer.py` 并从工具包导出：

| 模型 | file_id 约束 |
| --- | --- |
| `ViewSessionFileArguments` | 任务附件目录中的规范小写 UUID，固定36字符，保留连字符。 |
| `ViewContractFileArguments` | 合同查询结果中的64位小写 SHA-256。 |

两者均要求 file_id，page_number 可省略或为 null，表示当前会话该文件的下一页；首次默认第1页。指定页码须为正整数，拒绝布尔值、字符串与浮点数。页数上限由查看器打开文件后按实际页数检查。禁止额外参数，用户、会话、目录和文件池不可通过工具参数传入。

每个参数在生成的 JSON Schema 上均具有独立且非空的 description，解释来源、格式和默认翻页语义。参数模型采用 strict 校验，不自动修剪或改写文件标识；对应处理器后续可以将 `arguments.model_dump()` 直接展开到所绑定查看器的 `view()`。已通过 `build_file_view_tools()` 生成 `view_session_file` 与 `view_contract_file` 的完整工具定义（版本 `file-view-tools-v2`），正式处理器由 build_file_view_registrations 生成，并由宿主加入主循环工具表。

---

两个工具描述直接围绕“返回一页图像、指定页或继续下一页、失败保留位置”编写。附件的 file_id 描述对应实际任务渲染中的“用户输入 → 附件 → 内部索引”，明确不能填写附件序号、文件名或展示名称。合同的描述只引用上下文已提供的文件标识，不虚构尚未实现的合同查询结果展示格式。UUID 与 SHA-256 的格式限制由 Schema 保留，不要求模型理解其业务存储含义。

page_number 的描述给出操作例子：上次看第3页，省略参数时打开第4页；重看第3页须显式传3。描述不包含缓存、权限装配或底层存储设计。工具整体描述直接写在各参数类的 docstring 中，build_file_view_tools 从类读取；字段说明仍写在 Field(description=...) 中。正式注册时复用同一参数类及其 docstring，不单独维护描述常量。

## 单文件模型实现

`FileModel` 是会话附件与公共合同共用的具体类。来源层负责定位和权限校验，提供 PDF 字节；文件身份由外层 `FileModelKey` 管理，模型不读取任意路径，不保存用户信息、阅读游标或展示轮数。

```python
with FileModel.open(pdf_bytes, config=render_config) as model:
    total = model.page_count
    page = model.get_page(3)
    png = page.png_bytes
```

打开复用现有 `inspect_pdf_openable` 检查，拒绝空内容、损坏或非 PDF、需打开密码和无页面文件。模型持有打开的 PyMuPDF 文档，首次取页才渲染；使用既有 `PDFPageRenderConfig` 控制视觉预算。`get_page` 接受从1开始的整数，拒绝布尔值、非整数及越界页码，返回不可变 `CompressedPDFPage`。同页重复访问复用同一对象；渲染失败不写入缓存。

`cached_page_numbers` 返回已缓存页码快照；`clear_page_cache()` 清空页面缓存但保留文档。`close()` / `await aclose()` 幂等关闭文件并清空缓存，关闭后取页报错，轻量总页数仍可读取。外部已持有的不可变页面不会被强制销毁，调用方也应及时释放引用。文件池已按文件数执行 LRU 淘汰，本类最多按需缓存整份文件的页面；尚未限制总内存字节数。

`await render_page(page_number)` 在线程中取得页面，返回独立 `image_url` 内容块，兼容既有页面解析接口；Base64 按需构造，不驻留在模型缓存。同步打开和取页可能耗时，异步宿主应在线程中执行并管理创建后对象的所有权。取消等待不终止已运行的底层线程；仍须由资源所有者完成清理。

所有文档打开、渲染与关闭共用项目级 PDF 锁，防止多线程调用 PyMuPDF 或关闭在途文档。该锁保障串行安全，不表示底层解析能并行加速。单文件生命周期、文件池和 FileViewer 编排已实现；正式来源与工具注册已由 CommunicationFileTools 接入。

## 文件池实现

`FileModelCache(max_files=...)` 与文件模型同在 `tool/file_viewer.py`，使用一个具体类分别实例化共享合同池和隔离会话池。`max_files` 为必填正整数，拒绝布尔值；容量分别由下述环境变量配置，后续宿主装配时传入对应值。

文件池容量配置：

| 环境变量 | 默认值 | 范围 |
| --- | --- | --- |
| `COMMUNICATION_CONTRACT_FILE_CACHE_MAX_FILES` | 32 | 全局共享合同文件池 |
| `COMMUNICATION_SESSION_FILE_CACHE_MAX_FILES` | 8 | 每一个会话附件文件池 |

对应 Settings 字段分别为 `communication_contract_file_cache_max_files` 和 `communication_session_file_cache_max_files`。两项独立解析，单位为文件数，必须为正整数；不是页数或内存字节上限。配置在启动时加载，修改后需重启。`.env.example` 与本地 `.env` 已补充默认值。正式启动创建共享合同池，首次进入会话 Agent Core 时创建附件池；分别将对应配置传入 FileModelCache。

| 接口 | 行为 |
| --- | --- |
| `put(file, model)` | 接管描述与模型；重复加入同一描述及实例为幂等。替换闲置同键模型会先关闭旧模型；在用则报 `FileCacheBusyError`。失败时传入模型仍由调用方负责释放。 |
| `with acquire(key) as model` | 受保护借用，未命中报 `KeyError`；获取成功更新访问时间及 LRU。退出正常或异常均归还，不提供裸模型 `get()`。 |
| `get_page(key, page_number)` | 内部借用并获取指定页，返回不可变页面；不隐式读取缺失文件，不记录翻页位置。 |
| `list_files()` | 返回不可变目录快照，包含文件描述、总页数、缓存页数、带时区的加入及最近访问时间、在用计数；按 LRU 顺序排列，不刷新访问时间。 |
| `invalidate(key)` | 关闭并移除闲置单文件；未命中返回 False，在用则报忙。 |
| `close()` / `await aclose()` | 拒绝新操作并等待借用全部归还，然后释放全部模型；成功后可重复调用。关闭失败尝试释放其余文件，保留失败条目并抛异常组，可重试关闭。 |

容量达到上限时，加入新文件优先淘汰最久未访问且未被借用的条目；全部在用则抛 `FileCacheFullError`，不接管新模型。访问顺序由有序容器维护，不依赖墙钟时间比较。同一个模型实例不能归属两个池或同池两个键；不同来源和隔离范围由完整 `FileModelKey` 区分，池本身不替来源层进行鉴权。

池采用同步锁与借用计数，支持工作线程共享。调用方不得在借用范围外持有可变模型、直接关闭池拥有的模型，或在自己的借用块内关闭整个池。`get_page` 返回的不可变页面可继续使用，池释放只移除自身引用。同步打开、取页和关闭可能阻塞；异步宿主应在线程执行，并使用 `aclose`。取消对后台关闭的等待不会取消实际释放。

acquire_or_load 已串行合并同键缺失加载并保护入池后的借用；总字节预算与 TTL 尚未实现，实际池装配与驱逐回调已接入。当前专项测试覆盖 LRU、目录不刷新访问、容量全忙、单文件替换/驱逐保护、模型所有权、读页异常归还、整体关闭等待与配置边界。

## 两类磁盘读取函数

读取函数与其他工具组件统一保存在 `tool/file_viewer.py` 并从工具包导出，均不负责打开 PDF 或创建模型。

- `read_contract_file(file_id, directory=None)`：默认从项目 `data/contract` 读取 `<file_id>.pdf`，只接受64位小写 SHA-256 标识；校验读取字节的哈希与标识一致。不接受 file_uri、路径或任意文件名。
- `read_session_file(file_id, authorize=..., directory=None)`：默认从会话数据库所在目录的 `upload` 读取 `<UUID>.pdf`，复用现有安全附件读取函数。只读取已落盘内容；不自动使用内存附件或触发保存。

两者均拒绝符号链接及非普通文件；目录由可信宿主注入，不作为模型工具参数。未找到文件返回 FileNotFoundError，非法标识或内容身份错误返回 ValueError，底层读取故障保留 OSError。

会话读取必须注入同步 `authorize(file_id) -> bool`，由宿主绑定用户和会话并检查附件归属、驻留与准入状态。读取前后均要求结果严格为 True，否则抛 PermissionError；UUID 和文件存在不构成授权。该函数应为线程安全的实际权限检查，正式装配通过 run_coroutine_threadsafe 桥接到历史服务事件循环并在历史锁内检查；不能直接把协程或永远返回 True 的函数用作授权函数。

```python
from functools import partial

contract_reader = partial(read_contract_file, directory=contract_directory)
session_reader = partial(
    read_session_file, directory=upload_directory,
    authorize=check_current_session_attachment,
)
```

`FileViewer` 通过 `resolve_file`、`read_file` 两个函数完成访问与自动重建，已核对来源描述、版本和引用。正式元数据定位函数与异步历史服务授权适配已接入。读取函数是同步磁盘操作，异步宿主需放到工作线程。

测试覆盖两目录读取、合同哈希不符、路径参数拒绝、会话拒绝/读取中撤销、缺失与符号链接；仅验证读取字节，不用这些测试字节模拟真实 PDF 建模。

## 正式循环装配

`app/service/communication_file_tools.py` 负责应用与会话生命周期，具体工具和参数仍统一定义于 file_viewer.py。bootstrap 创建一个共享合同池；CommunicationWorkflowService 在门禁通过后按驻留会话取得两个注册项及组合页面解析器，分别通过 additional_tools、page_resolver 传入 run_agent_core。正式工具共七个：工作区增删改、中途输出、最终输出、view_session_file、view_contract_file。

两个注册项从参数类 docstring 取得整体描述，直接使用对应 Pydantic 模型；成功内容声明 foldable。参数/执行错误仍为普通结果，所有调用继续先走 FIFO 管理。工具进度采用默认“正在思考”，不额外发送正文 SSE；只有中途输出和最终输出工具发布用户正文。

每个驻留会话保存独立附件池、两个查看器与页面路由器，跨任务复用游标；合同模型池全局共享。会话权限检查以实际 SecretStr 密钥与 residency_id 进行，不能把显示用户名当作密钥。工作线程通过历史服务 file_tool_access 在事件循环和历史锁内校验；缓存命中也检查磁盘来源与身份。会话删除/驱逐时先立即撤销读取资格，再调度异步释放，避免持有历史锁等待反向查询历史的线程；应用关闭排空清理并关闭全局池。

正式合同查看器从注入的 SQLite 合同元数据存储读取 `file_name`，原样用于工具结果和页面描述，不追加 `.pdf`，不使用哈希作为展示名称；磁盘寻址仍使用合同 ID。缓存命中时也读取名称；元数据缺失或名称为空时返回 `file_unavailable`，不伪造展示名称。

会话附件依当前读取约定只从 upload 读取。新附件即使已通过门禁、仍仅保存在内存且尚未落盘，也会返回 file_not_found（文件不存在或尚未保存）；不暗中保存文件或回退内存。附件摘要仍正常进入上下文。合同查询工具尚未实现，查看合同需已有合法文件标识。

离线联调使用真实 PDF 与模拟模型验证正式门禁后工具注入、执行、下一轮图片展示、持久化折叠、已落盘附件、跨会话拒绝、共享池与会话独立池、删除撤销及资源清理；不请求 vLLM。

## 已实现接口与容量边界

`run_agent_core(..., page_resolver=resolver)` 接受异步解析函数：`resolver(ToolPageReference) -> list[dict]`。表格和长文本返回标准 text 内容块，图像返回 image_url 内容块。解析器负责从受权资源取得内容；窗口不读取任意文件路径，也不负责查询重建。没有正式查看工具时，可注入测试注册项验证整条链路。

`PageDisplayWindow.register(call_id, result)` 登记成功回执，`inject(messages)` 在原 tool 消息后注入提醒与页面，`consume(..., finish_reason=...)` 在 stop/tool_calls 完整响应后将本轮展示的各批剩余次数减1，耗尽后折叠，`close()` 清理引用。重新打开同页必须使用新 display_id；缺失回执锚点、重复展示标识、资源解析失败或内容形式不符均停止，不自动重放已执行工具。

`render_tool_receipt()` 供 FIFO 和驻留会话共同使用，只序列化普通结果及带来源定位的隐藏占位。实际可见请求会派生出“完整内容见临时资料”的说明；图片及整表不写入权威任务轨迹、摘要输入或持久化存储。程序不将隐藏占位当作已读事实；重启后只能看到轻量引用，需工具重新打开。工具不得将完整页面偷偷写入普通 tool_result 字段。

完整请求计数在页面注入之后执行，包含提醒、文本、图片及输出预留；超出上下文上限即停止生成，不静默丢弃页面或再次执行工具。FIFO 管理期间保留的是轻量回执，任务计数按这些实际轨迹进行；临时页面由完整请求容量检查兜底，不改变工作区/FIFO配额比例。当前不自动拆分或缩减单次过大的页面返回。

独立 FIFO 图默认不声明展示能力，继续对 foldable 返回 unsupported_content；主循环明确传入 supports_foldable=True 后，FIFO 才接受引用并继续。图内不消费展示机会。FIFO 状态显式包含 content，避免图执行时丢失类型与页面引用。

离线验证覆盖可配置轮数的展示、多页图表、重新打开、窗口隔离、截断与解析失败不消费、锚点校验，以及正式生成循环中进度输出后的折叠、完整请求计数和驻留/落盘仅保留引用。测试不访问 vLLM，不代表真实视觉模型或资源分页工具已经验收。

文件查看已完成正式装配的离线联调，git diff --check 通过；未调用 vLLM，表格查询仍未实现。

## 展示轮数配置与持久化

环境变量 `VLLM_MLLM_PAGE_DISPLAY_ROUNDS=5` 对应 `MLLMSettings.page_display_rounds`，必须为正整数，默认5；设为1可恢复单轮展示。配置在启动时读取，修改后重启后端生效。`.env.example` 与本地 `.env` 已同步。

每次打开获得新的展示标识和独立计数。页面前提示剩余次数（包含当前轮），最后一次增加保存提醒。请求构造、计数、网络错误和截断不减少次数；完整返回后减少，即使内容不符合工具协议。后台保存不消耗次数，不改变内存可见状态。

完整内容和剩余次数都不落盘。数据库只保存原工具调用、普通回执、资源定位及隐藏占位；重新加载会话后默认已折叠，不调用解析器、不重渲染旧页面，也不重新发放5轮机会。尚未终止的生成循环可继续使用内存窗口；任务退出会清空展示引用，不销毁解析器持有的会话资源。
