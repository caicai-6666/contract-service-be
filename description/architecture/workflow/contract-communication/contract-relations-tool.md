# 合同一跳关联查看工具

当前已实现工具模块与渲染器，统一位于 `agent_core/tool/contract_relations.py`；已注册到正式主循环。bootstrap 注入关系服务与 SQLite 元数据存储，宿主按驻留会话创建查看器，注册工具并将页面解析接入组合解析器；驱逐、删除会话或关闭服务时关闭查看器，清理快照并撤销迟到请求的读取资格。

## 接口与职责

`view_contract_relations(document_id, page=None)` 接收完整合同 ID 和可选页码。固定查询一跳，不递归，默认每页5条。首次省略页码从第1页开始，后续省略则下一页；显式指定第1页刷新。末页返回 `end_of_results`，非法页返回 `invalid_page`，均不移动游标。无关联为正常成功，页数为0；查询故障为错误，不能解释为无关联。

`ContractRelationsViewer` 直接依赖现有 `ContractRelationService.list_relations`，不经过 HTTP。按创建时间降序、关系 ID 升序建立快照。每个实例默认最多10个起点合同，LRU 保存关系 ID、资源身份和游标，不保存页面正文。驱逐后再次调用重新加载；省略页码从第1页开始，并提示重新加载。刷新会使旧页面引用失效。

页面解析实时获取当前关系及本页对方合同名称。现有服务没有按关系 ID 批量读取接口，因此当前每次读取都会查询起点的一跳列表；分页限制展示数量，不限制图查询数量。原快照中的关系或对方合同失效时保留位置并提示刷新，新关系在刷新后进入快照。分页期间不保证跨数据库事务快照。

## 展示与边界

渲染包含起点名称与完整 ID、页码、快照总数，以及对方合同名称、完整 ID、关系 ID、描述、创建人和带 `+08:00` 的创建时间。名称不追加 PDF 扩展名，关系描述原样展示，明确属于用户填写的联系，不能据此推断法律效力。

有内容的页面返回 `foldable` 轻量引用；空列表返回 `ordinary`。签名限定页面引用属于当前查看器，页面解析不会推进游标。已释放资源返回可读提示；失效签名拒绝解析。SSE 采用注册表默认 `thinking`，不单独产生用户正文。

工具用途说明强调快速理解合同之间的联系、定位后续阅读对象，适用于明确关联查询或分析中的背景补充。`document_id` 参数要求原样复制完整64位小写十六进制ID，禁止缩写、截断、省略号、首尾片段或名称替代；只有缩写时须先取得完整ID，不得猜测补全。

所有参数均由独立 Pydantic 模型定义并具有字段描述。模型可见的工具说明包含分页、刷新和信息来源边界。运行时装配、会话鉴权、会话释放回调由宿主负责，当前模块本身不授予访问权限；正式宿主仅在会话鉴权及业务门禁通过后装配工具。

## 验证

`tests/test_contract_relations_tool.py` 覆盖分页、末页与非法页区分、刷新、关系删除后的实时渲染、LRU、跨查看器引用隔离、清理、空结果、查询异常及默认展示状态。不依赖真实 Neo4j 或模型服务。

正式宿主联调测试 `tests/test_communication_relation_tools.py` 验证工具通过 FIFO 执行、真实渲染文本注入下一轮生成，以及删除会话后的读取撤销。

## 驻留容量配置

`COMMUNICATION_CONTRACT_RELATIONS_CACHE_MAX_CONTRACTS` 控制每个会话关联快照池容量（默认10），`COMMUNICATION_CONTRACT_RELATIONS_PAGE_SIZE` 控制每页关系数（默认5）。均通过 Settings 与环境变量加载，要求正整数；修改后重启服务生效。分页工具定义按实际页大小生成，不改变已有页码语义。
