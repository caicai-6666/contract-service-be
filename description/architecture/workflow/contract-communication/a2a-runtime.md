# A2A 子平台任务运行时

> **用途：** 合同平台通过中间件接收跨平台任务，首次判断是否受理，后续按 `response_id` 接续内存推理链。复用 [Agent Core](agent-core.md)，不经过 exploration 的业务门禁，不创建 SSE 会话或持久化记忆。

---

## 职责与依赖

| 模块 | 职责 |
| --- | --- |
| `app/infrastructure/a2a.py` | 平台令牌认证、用户本平台文件等级查询、任务领取和回复发布的 HTTP 适配与严格响应校验。 |
| `app/service/a2a_worker.py` | 后台窗口领取、显式续租、并发任务调度、交付重试及失租终止。 |
| `app/service/a2a_response.py` | 内存响应检查点、用户与来源平台隔离、任务幂等、上下文过期和交付前权限复核。 |
| `a2a/admission.py` | 广播认领的low强度单工具受理判断及私有审计。 |
| `a2a/access.py`、`a2a/contracts.py` | 服务端文件可见范围、只读元数据与关系代理，以及受限合同工具和页面解析器。 |

运行时依赖现有中间件平台会话、MLLM、SQLite 合同目录和正式 PDF；图像检索复用 ES，关系列表与检索复用 Neo4j。未增加第三方依赖。跨平台字段以中间件的 `description/api/platform-a2a.md` 和 `description/api/user.md` 为外部契约；本项目只实现子平台消费端，不提供新的公开 HTTP 路由。

## 首次受理与响应链

1. 首次广播请求没有 `response_id`（单目标首次请求同样走广播反馈流），程序注入统一 `system-guidence`，只公布 `accept_task` 并强制指定该工具。广播认领固定采用开启原生thinking的 `low` 配置副本和独立客户端，以尽快响应；不修改全局主模型配置，续聊仍沿用全局强度（当前为 `xhigh`）。参数只有严格布尔 `accepted` 与简要 `message`；此时不装配合同查询、不执行业务处理。
2. `accepted=false` 返回 `not_applicable` 与说明，不生成响应 ID。`accepted=true` 返回 `succeeded`，程序生成不可预测的 UUID 响应 ID，保存原始输入、完整已接受原生 thinking、函数调用及回执。
3. 续聊必须引用本进程仍驻留、未过期且属于同一 `userid` 和来源平台的响应。恢复完整历史及工作区后，通过 `run_a2a_task` 执行，最终仅用 `finish_task` 提交一次结果；每次成功生成新的响应 ID。
4. 同一响应链共用异步锁，等待期间再次校验有效期；引用旧检查点会从该检查点创建分支。不同用户、不同响应链可以并发。同 `task_id` 的相同输入复用执行与结果，冲突输入拒绝。

错误调用只用于本轮纠错，成功后的历史只保存已接受轨迹；包括被拒绝响应在内的审计保留在私有内存，不发给调用平台。失败返回 `failed`，历史引用缺失、权限收缩或过期返回 `context_expired`，均不生成新 ID。程序不把未验收正文或失败工作区发布为成功状态。

所有检查点、任务回执和审计均有数量上限。响应 TTL 从该检查点生成时计算；过期检查点在下一次处理请求时清理。进程退出或重启会清空上下文；无数据库表、磁盘归档、会话记忆加工或记忆检索工具。完整历史超出模型上下文或管理预算时失败停止；当前内存宿主不接受摘要替代历史，也不截断原生 thinking。

## 无感文件过滤

`POST /middleware-service/api/user/file-permission` 使用本平台 Bearer Token，请求体仅 `{"userid":"..."}`，平台代码由中间件识别。成功响应固定为 `{"file_level":0}` 或 `{"file_level":null}` 等单字段对象。严格非负整数有效，`0` 不是缺失；`null` 表示无本平台文件授权。负数、布尔、字符串、浮点或额外响应字段均拒绝。401 使当前平台令牌失效；接口故障、异常响应或无有效令牌时不放行文件。

模型看不到用户等级、权限响应、平台令牌或交付凭证，也不能通过参数指定这些值。程序仅允许读取本平台正式 `ready` 合同，且文件等级必须已知、非负并不超过用户当前本平台等级；管理员没有旁路。

过滤覆盖：

- `search_contracts` 的初始范围、父候选交集、子查询、最终结果及数量；空范围保持显式空集合，不回退全库。
- `view_contract_file` 的定位、读取、缓存命中与页面重新解析；只通过本平台正式合同目录读取。
- 元数据、注意事项、通行证列表、图像检索源文件与候选，以及关系列表、关系检索和库统计。关系两端都需可见，Neo4j 在候选上限之前应用可见集合。
- 列表数量、分页、备注数量、类型与上传人分布、关联覆盖统计，均只计算可见合同。

A2A 不提供 `view_session_file`、`search_memory` 或 `view_memory_query`；图像相似检索的 `source_type` 固定为 `contract`，不能改用用户附件。合同扩展工具必须绑定私有访问策略，拒绝装配未过滤工具。

每次读取模型上下文、合同工具执行前后、页面解析前后及结果交付前均重新校验。历史思考可能含正文、摘要和统计，因此保守追踪历史当时的全部可见合同；只要该集合收缩，就使整条响应链的检查点失效，不能只过滤新工具结果。权限恢复不会复活已失效的链。接口暂时故障时停止处理，不把旧等级当作有效缓存。

结果池及 PDF 页面池按一次执行隔离并在结束时释放，旧工具引用跨任务需要重新查询。不可见 ID 和不存在 ID 返回同一反馈，不说明隐藏文件或实际权限等级。

## 领取、续租与交付

子平台调用 `platform-a2a/requests/pull`，使用新的 `Idempotency-Key` 领取或显式续租；不传旧 `limit` 参数。一次响应同时处理 `tasks` 与 `renewed_tasks`。未知领取结果保留原键、原续租参数重试；回放空批次后下一次新操作换键。

处理完成调用 `platform-a2a/replies/publish`，只提交任务 ID、交付凭证、状态、message 和可选 response_id。201 的 `saved` 与 `discarded` 均完成原任务并释放窗口，不调用已移除的 `requests/ack`。

- 429 表示单聊反馈队列满：保留生成结果并续租，稍后重发，不重跑模型。
- 503、传输故障或无法确认的回执：冻结原载荷与凭证重试，不将可能已完成的任务加入续租。结果权限复核不再通过时，停止旧交付，等待重领，不能改写已尝试发布的幂等载荷。
- 409 表示旧交付失效：停止旧执行；整批续租冲突无法识别失效项时，保守停止该批旧执行，随后用新键重新领取。租约到期会终止旧模型任务。
- 重领使用新凭证；进程中已有生成结果可复用，但必须重新复核响应有效期及文件权限。

任务处理与网络请求使用现有超时与并发资源；日志只记录操作失败的异常类型，不输出消息、等级、身份和令牌。

## 配置与验证

默认 `A2A_ENABLED=false`。启用时需配置现有 `MIDDLEWARE_BASE_URL`、`MIDDLEWARE_PLATFORM_CODE`、`MIDDLEWARE_SECRET`，且中间件已将本平台登记为支持 A2A 的子管理平台；服务启动装配、关闭时先终止 A2A，再关闭平台会话及业务资源。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `A2A_CONTEXT_TTL_SECONDS` | `1800` | 响应检查点存活秒数。 |
| `A2A_CONTEXT_CAPACITY` | `100` | 内存响应检查点数量上限。 |
| `A2A_RECEIPT_CAPACITY` | `1000` | 任务幂等结果及私有审计数量上限。 |
| `A2A_POLL_INTERVAL_SECONDS` | `2` | 后台轮询及续租周期秒数，需小于中间件任务租约。 |

使用项目 conda 环境运行 `python -m unittest discover -s tests`。A2A 回归包括真实共享循环、强制受理、完整 thinking 接续、用户隔离与过期、权限收缩及缓存复核、真实临时 PDF 页面、SQLite 统计、查询范围与父排名、关系双端过滤，以及 MockTransport 模拟中间件收发和不确定重试。上述离线回归不发送真实跨平台任务、不调用真实模型。2026-10-26 已另用真实 HTTP/Redis/模型及隔离空库完成10个子任务的首次受理、完整上下文续聊、拒绝、显式内存失效和迟到回复验证，见[真实联调分析](../../../../experiment/platform-a2a-live/output/20261026T124337.598962Z/analysis.md)。本轮未验证真实合同检索、原文阅读、权限收缩或实际 TTL 时长；实验产物依项目规则仅本地保留。

## 本地启用记录

2026-10-26 已按用户要求在本地 `.env` 设置 `A2A_ENABLED=true`，并从命令行重启合同后端，以装配 A2A Worker；知识后端同时开启发送工具与反馈接收。中间件未在本次操作中重启。此记录仅描述本地环境，其他环境仍需显式启用；本次未发送业务测试请求。

广播认领配置由 `MLLMSettings.for_a2a_admission()` 生成；生成与token计数使用相同的low模型适配，Qwen为low、GLM为low、DeepSeek为50。仅对本地模型控制强度，跨平台消息本身不增加推理强度字段。认领客户端与正式续聊客户端分别装配；测试注入分别使用 `admission_client` 和 `client`，避免复用绑定xhigh的客户端导致低强度配置未生效。`tests/test_a2a_admission_effort.py` 验证独立配置、真实请求体与分词参数一致，以及生产分支先low后全局xhigh。

广播认领允许单个合法accept_task原生调用附带content，附文只留审计；accepted/message仍须通过Schema与业务校验，成功历史content=null。失败反馈只包含安全的字段类型/约束与认领阶段修正方向。feedback_delivered仅在下一轮请求返回后确认，最后一次达到限额的诊断不会被伪称送达。
