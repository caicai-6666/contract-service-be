# 合同注意事项查看工具

`tool/contract_notes.py` 统一定义参数、查看器、渲染器和注册入口。`view_contract_notes` 已接入正式 Agent Core：会话鉴权与业务门禁通过后装配，经 FIFO 和 Executor 执行；页面经组合解析器注入上下文。

## 使用与渲染

当需要了解用户为合同补充的提醒、风险提示或其他注意事项时使用。输入完整64位小写合同 ID，禁止缩写或名称替代。可选 page：首次省略查看第1页，后续省略查看下一页；显式指定1刷新。末页不循环，非法页不移动游标。

按创建时间降序、同时间注意事项 ID 升序展示，优先最近新增记录。排序在工具层完成，不改变既有注意事项 HTTP 接口的排序。页面包含合同名称和完整ID、当前页/总页数/快照记录数、各条原始内容、撰写人、带UTC+08:00的创建时间和翻页提示。明确注明用户记录不是合同原文，不代表事实已核实。

## 驻留与读取

每个驻留会话有独立查看器，跨任务复用；LRU只保存每份合同的注意事项ID有序快照和游标。SQLite读取在线程中执行，不缓存正文。当前复用 list_notes，每次读取完整列表后按快照选取本页；分页限制展示量而非SQL读取量。

新增记录刷新后进入快照；旧记录被删除时原位置标注失效，刷新后移除。驱逐后重新调用会加载新快照，省略页码从第1页开始。刷新或驱逐使旧页面资源失效；页面引用签名按查看器隔离。会话驱逐、删除或服务关闭时释放并撤销迟到查询资格。

## 返回与错误

有内容返回 foldable 轻量引用，无记录返回 ordinary 成功结果。SSE采用默认 thinking，无单独用户正文输出。暂无记录、end_of_results、invalid_page、contract_unavailable和query_failed分别反馈；数据库失败不会被解释成暂无记录。合同不存在、入库未完成或删除中均不提供正文。

## 配置

- `COMMUNICATION_CONTRACT_NOTES_CACHE_MAX_CONTRACTS=10`：每个会话驻留合同数量。
- `COMMUNICATION_CONTRACT_NOTES_PAGE_SIZE=5`：每页记录数量。

均要求正整数，由Settings经bootstrap注入正式宿主；修改后重启生效。工具描述中的每页数量随配置生成。

## 验证

`tests/test_contract_notes_tool.py` 验证排序、分页、删除、刷新、LRU、释放、错误反馈和工具定义。`tests/test_communication_relation_tools.py` 验证正式宿主注册、下一轮生成收到页面正文以及会话删除清理。测试使用隔离数据与模拟模型，不修改正式业务记录。
