# 按用户备注检索合同

`search_contracts_by_notes` 根据用户记录的风险提醒、处理经验、补充说明和待关注事项查找合同。检索只针对备注正文，不把用户意见视为合同原文或已核实事实。现作为[合同候选查询子图](contract-retrieval.md)内部工具，不直接注册给主模型，也不提供查看或分页工具。

---

## 工具契约

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| `query` | 是 | 根据已有线索拟写的用户备注，去除首尾空白后 1–10000 字符；采用自然的陈述或提醒语气。 |
| `result_id` | 否 | 本次子图调用的内部结果集完整 ID；省略或 null 查询全库 ready 合同，空字符串非法。 |

查询应贴近用户实际备注的表达，突出已知观察、风险、提醒或待确认事项，不直接照抄查找请求。例如“找被提醒回款有风险的合同”改写为“需关注该合同的回款风险。”仅在已知拖欠事实时加入“客户存在拖欠货款的情况”，不能为了丰富查询而补造原因、进展或事实。保留已有名称、编号、条件、否定和不确定性；作者与日期仍不提供精确筛选。检索同时利用词项与语义线索。可使用图片、问题或备注检索生成的结果集限制候选合同。失效引用报错，不能退回全库；查询过程中驱逐引用或释放会话时不发布新结果。旧集合和分页游标不改变。

非空成功仅返回 `status`、`result_id`、`count` 和提示，不展开名单，无查看工具。零结果返回 count=0 和提示，不创建引用或占用 LRU。编码、索引、数据库错误返回失败，不伪装为空结果。工具只读共享正式合同；会话结果引用仍按驻留会话隔离。

## 召回与合同归并

1. 查询复用 `contract-note-v1` 正文编码指令，保留条件、否定与不确定性，执行响应校验和 L2 归一化。
2. 在 SQLite 同一读取快照中进行两路召回：FTS5 BM25 使用 Lindera（Jieba），向量使用 sqlite-vec 余弦距离。只允许 ready 合同，范围限制在各路排序截断之前生效。
3. 每路最多取 `min(top_k × 4, 200)` 条备注。备注按等权 RRF 排名，公式为 `sum(1 / (60 + rank))`，rank 从 1 开始。缺席某路的备注该路贡献为零，不按命中路数调整分母。
4. 同一合同取其最佳命中备注的融合分数，不累加多条备注分数；保留该备注 ID 作为分页依据。最终截断为 top_k 份合同。并列备注按 note_id、并列合同按 document_id 确定顺序。

旧备注无向量或向量模型、版本、维度不兼容时仍能参加 BM25，不自动重算向量。向量候选没有最低相似度门槛，RRF 不是相似度或概率；结果是有限候选，不是符合某业务条件的完整清单。当前向量查询为过滤后的精确扫描，数据规模增长后需评估索引优化。

## 索引与生命周期

`app/infrastructure/contract_note_search.py` 维护 `contract_notes_fts` 外部内容索引和增删改触发器。元数据初始化时首次建立并回填历史正文；重复初始化不重建。新增、删除、正文更新及合同级联删除在同一事务同步索引。所有合同元数据连接加载 Lindera 和 sqlite-vec，缺失依赖明确失败，不能静默换分词器。脚本直接写数据库时也必须使用支持这些扩展的连接。

自然语言先经相同分词器切词，再逐词转义构造 OR 查询，不执行输入中的 FTS 运算符。作者、时间不参与正文索引。

内部结果池保存合同 ID、RRF 分数和查询方式，不保存备注正文；命中备注用于底层排名，不再供内部模型展开查看。最终由子图回读合同列表，详见[候选池规则](contract-retrieval.md)。

## 配置与依赖

`COMMUNICATION_CONTRACT_NOTE_SEARCH_TOP_K` 默认 10，范围 1–50。结果池复用 `COMMUNICATION_CONTRACT_SEARCH_CACHE_MAX_QUERIES` 和 `COMMUNICATION_CONTRACT_SEARCH_PAGE_SIZE`。模型和分词配置沿用 Embedding、SQLite Lindera 配置；备注检索及分页不依赖 ES 客户端是否注入。问题检索仍保持原来的纯向量实现。

实现入口：`agent_core/subgraph/contract_retrieval/tool/contract_note_search.py`。存储边界见[合同元数据](../../data/contract-sqlite-metadata.md)，分页机制见[合同图像检索](contract-image-search.md)。
