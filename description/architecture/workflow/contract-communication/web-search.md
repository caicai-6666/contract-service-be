# 网页搜索与正文读取工具

> **状态：** `search_web`、`view_web_search_results`、会话 LRU 结果池及主循环接入已实现。首次打开网页的 `web_page` 子图已实现 HTTP 拉取、Trafilatura 正文提取及模型精炼；`open_web_page`、会话正文缓存、分页和主循环接入均已实现。

本模块让主助手先搜索候选网页，再自行选择来源读取正文。搜索摘要只能帮助选择来源，不能等同于已经读取网页。实验入口见[网页搜索与提取报告](../../../../experiment/web-search-extraction/REPORT.md)，工具接入遵循[主助手工具执行](tool-execution.md)，展示与资源生命周期遵循[页面内容折叠与资源建模](page-content-management.md)。

## 三个工具的职责

| 工具 | 参数 | 职责与成功返回 |
| --- | --- | --- |
| `search_web` | `query` | 使用 DDGS 搜索，建立候选结果集，仅返回 `result_id`、`count`，不自动展示第一页。 |
| `view_web_search_results` | `result_id`、可选 `page` | 查看搜索结果集指定页；省略页码时查看下一页。 |
| `open_web_page` | `source_id`、`focus`（首次必填）、可选 `page` | 首次拉取、提取并缓存网页正文；再次调用读取缓存并翻页。 |

只暴露这三个工具。网页正文的首次打开和后续翻页由同一个 `open_web_page` 承担。

`query` 使用简洁搜索关键词或短语，组合检索对象、关键条件以及必要的时间、地域，避免寒暄、冗长背景和输出格式指令。例如“上海 企业采购合同 电子签章 效力”。`result_id` 必须使用工具返回的完整结果集标识。每条候选由程序分配稳定的 `source_id`，同时展示标题、URL 和明确标注的搜索摘要；`source_id` 不使用随翻页变化的行号，打开时必须原样传入。页码从 1 开始。

搜索成功但没有结果时，返回“未找到符合条件的网页”等提示，不生成结果集 ID。服务异常、网络失败或超时应反馈对应错误，不伪装成零结果。

## 网页打开与内容精提

正文未缓存且来源仍有效时，执行以下顺序：

1. 根据 `source_id` 解析 URL，通过 HTTP 拉取 HTML。
2. 使用 Trafilatura 提取正文。
3. 提取结果非空时，调用模型判断是否存在有效信息，并清理正文。
4. 通过检查后缓存正文，返回请求页；未指定页码时返回第一页。

任一步失败，立即停止本次调用后续流程。这里的“熔断”只结束当前工具调用，不结束用户任务；主助手可以选择其他搜索来源。

| 阶段 | 失败或受限情况 | 处理方式 |
| --- | --- | --- |
| HTTP | 请求失败、超时、不可用响应 | 返回读取失败原因，不调用正文提取和模型。 |
| 正文提取 | 提取异常或没有正文 | 返回提取失败或无正文提示，不调用精提模型。 |
| 模型精提 | 只有登录、验证、导航等内容，没有有效信息 | 返回无有效内容及原因，不建立成功正文缓存。 |
| 模型精提 | 模型请求失败或输出不符合契约 | 返回处理失败，不发布半成品正文。 |
| 模型精提 | 有部分有效信息，但存在访问限制或内容缺失 | 允许返回可用内容，同时明确提示限制。 |

HTTP 成功、提取文本非空，都不代表获取了有效正文。页面带有登录入口也不直接判为失败，应根据实际可读取内容判断。初版采用 HTTP 读取，不包含自动登录、验证码处理或浏览器执行流程。

### 精提边界

模型围绕输入的自然语言重点 `focus` 提取相关事实，同时保留必要上下文、条件与限制；没有相关有效信息时返回提示。成功内容为一段精炼文本。去除导航、广告、无关推荐及重复片段，保留事实、必要结构、来源条件和可见的访问限制；不得补写缺失事实、猜测价格对应商品、把受限页面描述为完整内容。

正文精提不能恢复 HTML 中未取得的信息，也不能恢复前一步已经丢失的内容。程序应保留 URL、抓取时间及必要的访问限制线索供模型判断，避免登录提示被 Trafilatura 去除后，模型误认为正文完整。搜索摘要与页面正文分开呈现，不用搜索摘要填补缺失正文。

精炼模型输出 `evidence`、`reasoning`、`type`、`result`。采用普通 Chat Completion，提示词说明字段要求，Schema 仅用于本地校验，不传服务端 `response_format/json_schema`。`type=content` 时 `result` 是精炼正文；`type=no_content` 时为友好熔断提示。无可用信息包括纯噪声、正文与关注重点无关、或相关信息无法可靠归属，不将这些原因混为一谈。HTTP 失败不会进入精炼模型。

## 资源池与分页

搜索结果集和网页正文分别使用会话内驻留资源池，采用 LRU 驱逐并隔离不同会话。结果集存储候选及来源映射；正文池存储精提内容、来源信息、必要提示和分页所需状态。精炼结果与 `focus` 相关，同一链接换关注重点后不得直接复用旧精炼结果；当前初版会重新抓取和精炼，不另建原始正文缓存。会话驱逐时释放这些临时资源，不作为永久网页档案保存。

搜索池和正文池配置见下表。正文池驱逐后，如果 `source_id` 仍能解析出有效来源，可以重新拉取和建模；来源映射也已失效时，提示重新搜索，不从标识猜测 URL。

| 场景 | 分页行为 |
| --- | --- |
| 搜索成功 | 只返回 ID 和条数，游标为 0；首次调用列表查看返回第一页。 |
| 网页首次打开或重新建模 | 未传页码返回第一页；传入页码则校验后返回该页。 |
| 已驻留资源，省略页码 | 返回当前页的下一页。 |
| 显式指定合法页码 | 返回该页并更新当前位置。 |
| 省略页码但已经到末尾 | 提示已到最后一页，给出当前页和总页数。 |
| 指定非正整数或超过总页数 | 提示页码非法及有效范围，不改变当前位置。 |
| 搜索结果集已失效 | 提示结果已释放，需要重新搜索。 |

每页展示来源标识、当前页和总页数；搜索页还展示候选总数。正文重新抓取后属于新版本，分页依据新正文重建，不承诺与旧版本页码内容相同。

## 上下文与状态接入

搜索结果页和网页正文页采用现有 `foldable` 返回契约。工具负责资源建模与页面内容，外层上下文管理负责展示提示和自动折叠；折叠不删除资源池对象。展示窗口沿用现有可配置规则，默认保留 5 轮工具调用，不单独引入一轮即隐藏的规则。

工具注册后通过现有 executor 执行，并经过 FIFO 外层管理。仅成功提交的内容进入权威状态，失败调用和纠错轨迹遵循[多轮上下文管理规范](../../../standard/agent-context-management.md)。网页内容属于外部资料，不能作为系统指令执行。

三个工具统一使用 `task.progress.type = online-search`，状态文字均以“正在”开头：

| 工具 | `message` |
| --- | --- |
| `search_web` | 正在搜索网页：上海 &#124; 企业采购合同 &#124; 电子签章 |
| `view_web_search_results` | 正在查看搜索结果 |
| `open_web_page` | 正在读取网页：关键词1 &#124; 关键词2（无可用重点时仅显示动作） |

状态消息只表示当前动作，成功或失败以实际工具结果为准。外部专家工具继续使用 `external-expert`，不与本模块的网页搜索状态混用。

## 当前实现与配置

工具、池、渲染器及参数模型位于 `app/agent/contract_communication/agent_core/tool/web_search.py`。`CommunicationFileTools` 为驻留会话创建独立池，复用应用内搜索并发额度；会话驱逐时关闭池并清除来源映射。页引用由池签发并校验，正文打开工具使用池的 `source(source_id)` 解析来源。

列表按 DDGS 返回顺序去重保存，仅去掉 URL 片段进行去重，保留查询参数。该顺序是搜索引擎相关性顺序，不输出未计算的相似度分数，也未引入向量或模型重排。网络或供应商异常返回失败，不当作空结果。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `COMMUNICATION_WEB_SEARCH_CACHE_MAX_QUERIES` | 10 | 每个会话最多驻留结果集数 |
| `COMMUNICATION_WEB_SEARCH_PAGE_SIZE` | 5 | 每页候选条数 |
| `COMMUNICATION_WEB_SEARCH_MAX_RESULTS` | 20 | 单次搜索候选上限 |
| `COMMUNICATION_WEB_SEARCH_TIMEOUT_SECONDS` | 10 | DDGS 底层请求超时秒数，并非整个聚合搜索的硬截止时间 |
| `COMMUNICATION_WEB_SEARCH_MAX_CONCURRENT_REQUESTS` | 2 | 应用装配的搜索服务并发上限 |

以上配置均为正整数。搜索不创建持久化记录，进程重启后结果集失效。同步工作线程在取消请求后可能继续到其底层超时；线程完成前仍占用并发额度，完成后也不能复活已释放的会话池。

离线验证：`python -m unittest discover -s tests -p test_web_search.py -q`。

## 首次打开网页子图

包位置：`app/agent/contract_communication/agent_core/subgraph/web_page/`。通过 `build_web_page_subgraph()` 构建 LangGraph，输入为 `request: WebPageRequest`，输出为 `result: WebPageResult`。

| 文件 | 职责 |
| --- | --- |
| `schema.py` | 输入请求与最终结果模型；成功正文非空，失败不得携带半成品 |
| `state.py` | 公开输入输出与内部 HTML、正文、精提候选状态 |
| `node.py` | HTTP 拉取、正文提取、模型精炼及统一收束节点 |
| `prompt.py` | 版本化的精炼规则、示例、输出字段说明和可读输入渲染 |
| `workflow.py` | 串联处理阶段，失败短路到尾部 |
| `__init__.py` | 导出构建函数与契约 |

执行路径：`START → fetch_html → extract_text → refine_content → finalize → END`。HTTP 拉取和正文提取节点根据 `error_code` 判断是否直接跳到 `finalize`；精提结果始终由 `finalize` 收束。`finalize` 是唯一连接 `END` 的节点。

输入仅包含 `url` 和必填自然语言重点 `focus`；来源标识由外层管理，子图不依赖搜索池。不传页码或结果池，子图只负责首次读取；成功后的缓存发布、分页、再次打开及主循环注册由外层工具负责。

成功的业务内容为 `result.content` 中的一段精炼文本；结果信封另保留状态、原始 URL、实际 URL、抓取时间、提示以及错误码和失败阶段，供外层处理。部分可读内容可在成功结果中附带限制提示。内部 HTML、初步正文和访问限制线索不会直接进入公开输出。请求校验错误由调用方按参数错误处理；后续实现的网络和模型异常应在对应节点转换为阶段错误，任务取消应继续向上传播。

三个处理节点均已实现，最终精炼成功后由收束节点返回正文。外层 `open_web_page` 已注册主循环，并实现正文缓存和分页。

HTTP 节点使用独立 `httpx.AsyncClient` 流式读取，不注入登录凭据。默认总超时 30 秒、最多 5 次重定向、解压后响应上限 3 MiB，可通过构建函数参数调整；这三个选项暂未新增环境变量。支持注入 `transport` 做离线验证。非成功 HTTP 响应、超时、网络异常、过多重定向、空响应和明确的非 HTML 类型均产生阶段错误。缺少 Content-Type 时交给正文解析器判断。原始字节保留至解析阶段，便于根据 HTML 编码声明识别中文。

Trafilatura 在线程中输出 Markdown，保留链接和表格、排除评论；额外从 HTML 可见文本提取登录、权限、验证等关键词附近的有限原文线索，当前仅保留为内部状态，不注入精炼模型。此线索为启发式补充，不能保证识别所有访问限制；页面出现登录入口不会直接熔断。空文本或仅标点文本返回 `empty_text`，其他非空文本是否相关有效由后续精炼判断。解析异常返回 `extraction_failed`。任务取消向上传播，线程取消等待不代表解析线程立即停止。

验证命令：`python -m unittest discover -s tests -p test_web_page.py -q`。覆盖重定向、中文正文和限制线索、HTTP 403/404、非 HTML、响应上限、空响应、循环重定向、超时与取消、空正文、解析异常、输入约束和子图短路；不依赖公网或模型服务。


### 模型精炼的保留边界与校验

提示词版本 `web-page-refinement-v4`。system 只描述阅读任务、事实边界、选材规则和输出格式，不注入完整机器 Schema 或程序处理流程；机器 Schema 由本地校验维护。先确认页面主体与信息归属，再按 `focus` 保留直接相关事实及防止误解所需的定义、条件、例外、时间、单位和限制。允许自行提取、改写和组织，删除无关和重复内容，可分段，不强制压缩到固定字数；必须保持对象归属、条件、否定、因果及时间关系。推荐商品即便同类也不能拼接进主商品；政策正文中不相关段落应排除，但不误称为噪声。归属不明确的事实舍弃，必要时说明限制；仍有有效部分时允许返回部分内容。

模型 JSON 输出契约由 `WebPageRefinement` 定义：`evidence` 为内容依据字符串列表，可摘录或概括，无相关依据可为空，`reasoning` 为简要判断依据，`type` 只允许 `content/no_content`，`result` 为非空正文或提示。通过项目统一的 JSON 兼容转换后进行本地 Pydantic 校验；不执行原文逐字匹配、摘要长度、选材或顺序校验；仅拒绝结构不合法、输出截断、拒答或工具调用。事实关系由提示词约束，程序不宣称已经验证事实正确。

默认最多 3 次生成，可通过 `max_attempts` 配置。失败响应只进入宿主传入的 `audit` 列表，下一轮只追加最小格式纠错信息；成功后清除纠错消息，不把 evidence/reasoning 或失败输出写入公开正文。审计记录保留提示词版本、原始响应、校验错误和接受结果；宿主需传入独立审计容器才能在子图调用后继续留存。服务异常返回 `refinement_request_failed`，连续校验失败返回 `invalid_model_output`，都不意味着网页无内容；有效的 `no_content` 返回对应提示。取消继续向上传播。

构建函数支持注入 `settings`、`client` 和私有 `audit`；默认创建并关闭 `MLLMClient`，复用现有生成预算、温度和思考开关。基础设施的普通 `MLLMCompletion` 新增可选正文、原始响应、拒答和工具调用标记，原有计数与结束原因字段保持兼容。未使用强制 JSON 接口。

离线节点验证另外覆盖：精炼成功、无有效内容、证据概括及空列表接受、输出截断、JSON 纠错后清理、服务异常与取消；模拟响应只能验证程序契约，不证明真实模型已能稳定区分推荐区和主体。


精炼节点的模型输入仅为 Trafilatura 输出的网页文本和 `focus`。原始 URL、重定向 URL 和抓取时间留在程序状态与结果元数据中，不单独注入模型；原始 HTML 及额外提取的访问提示也不注入。文本本身包含的链接或登录提示仍作为文本的一部分保留。提示词和内容依据均以实际传入的文本为边界，无法恢复前一步已删除的信息。


真实网页与 MLLM 的七用例联调见[网页精炼实验报告](../../../../experiment/web-page-refinement/REPORT.md)：覆盖政策不同重点、长技术文档、主商品与推荐区、空正文及附件入口；区分语义质量与逐字证据校验失败。


版本 v4 已移除此前额外引入的证据逐字匹配；历史实验中的证据拒绝结论仅描述当时版本，原始产物不变。当前只做输出协议与字段结构校验，选材、概括和组织由模型完成，必须遵守事实关系。

## 网页打开工具接入

实现文件为 `app/agent/contract_communication/agent_core/tool/web_page.py`，包含 `OpenWebPageArguments`、`WebPageViewer`、渲染器和注册工厂。`CommunicationFileTools` 为每个驻留会话创建独立查看器、注册工具并路由 `web-page:` 页面引用；会话驱逐时关闭缓存。工具通过原有 registry/executor 和 FIFO 路径进入主循环，状态为 `online-search` / `正在读取网页`。

调用方式：首次 `open_web_page(source_id, focus)` 返回第一页；随后 `open_web_page(source_id)` 沿用该来源最近使用的驻留关注重点并查看下一页。可显式指定页码；传入新的关注重点时重新抓取和精炼。缓存以 `(source_id, focus)` 为键，不做语义相似匹配，同一来源的不同重点分别占用缓存条目。省略 focus 且不存在可用缓存时返回 `focus_required`，提示补充重点，不猜测此前需求。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `COMMUNICATION_WEB_PAGE_CACHE_MAX_ENTRIES` | 10 | 每会话最大驻留精炼结果数，正整数，LRU 驱逐 |
| `COMMUNICATION_WEB_PAGE_CHARS` | 3000 | 正文每页最大字符数，正整数 |

只缓存成功的最终精炼正文及来源、抓取时间和分页状态，不缓存失败、HTML 或初步正文。按字符顺序切分，不丢字、不重新摘要；可能在段落内部断页，连续页拼接可恢复完整正文。渲染展示标题、来源 ID、链接、抓取时间、重点、当前页和总页数。

缓存命中不调用 HTTP 或模型；正文被驱逐且来源仍有效时，提供 focus 可重新读取。缓存仍在时，即使搜索结果集已被驱逐仍可阅读已有正文；需要重新抓取但来源已失效时返回 `source_expired` 并提示重新搜索。来源与正文缓存均不跨会话共享、不落盘，进程重启后失效。

每次查看签发新的带签名页面引用，符合独立展示窗口契约；正文只经 `foldable` 解析注入，不放入普通工具反馈。旧引用不会指向后来重新抓取的正文；资源驱逐后解析只返回重新打开提示，不隐式重抓。显式非法页和自动翻到末尾分别返回 `invalid_page` 和 `end_of_results`，不移动游标。

子图错误原样转换成失败工具反馈；未知异常返回友好错误。请求前后都检查会话访问资格，驱逐后迟到请求不能重新建立缓存；取消向上传播。查看器在内存保留最近若干次子图调用的完整私有审计（上限与缓存条目数相同），不会注入模型或前端，并随会话释放。

离线测试：`test_web_page_tool.py` 覆盖缓存命中、不同重点、LRU重建、空结果失败不入池、来源失效、签名与会话隔离、晚到结果撤销；`test_communication_file_tools.py` 验证主循环注册、正文注入、终态折叠存储和会话删除释放。子图的真实模型实验不等同于已验证主模型自主选择和调用工具的质量。


网页打开工具支持可选 `keywords`：模型从关注重点概括最多5个简短关键词，每项不超过24字符。注册表在参数校验后通过 `progress_factory` 生成 `正在读取网页：处理器 | 内存 | 价格`，仍使用原有 `task.progress.message` 字段和 `online-search` 类型，无新增 SSE 事件。关键词只用于展示，不传给提取子图、不改变缓存键。省略时从当前 focus（或缓存中沿用的 focus）按常见分隔符生成简短片段；没有可用内容时回退固定状态。结束或失败后仍恢复“正在思考”。


`search_web` 的动态状态直接来自已校验的 `query`：按空白、逗号、顿号和分隔符拆分展示为 `关键词 | 关键词`，不增加模型参数，不改变实际搜索词。状态总长遵守2000字符限制，超出时省略；仍通过 `online-search` 的 `task.progress.message` 发布，执行结束恢复“正在思考”。
