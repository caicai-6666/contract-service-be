# 按问题检索合同

`search_contracts_by_question` 帮助 Agent Core 寻找可能回答某个业务问题的合同。合同入库时依据内容生成一组检索问题，本工具使用这些问题形成的合同级融合向量进行召回，不生成答案，也不将相关性当作已核实的合同约定。

已移入[合同候选查询子图](contract-retrieval.md)，只对内部 Agent 提供；主模型通过 `search_contracts` 获取最终列表。

---

## 工具契约

工具参数只包含以下两项，实际 Schema 的每个字段均有说明：

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| `query` | 是 | 将检索意图改写为用户直接向合同提问的自然问句，保留已知主体、事项、条件和否定，不预设答案或补造事实；去除首尾空白后不能为空。 |
| `result_id` | 否 | 本次子图调用的内部结果集的完整引用；省略或 `null` 使用本次初始范围，未限定时全库查询，非空引用限定候选范围。空字符串非法。 |

不直接照抄查找请求。例如“找涉及延期交付责任的合同”改写为“交付延误时，需要承担什么责任？”。已有主体线索时保留，未知时不猜测。另一个示例问题：“设备验收不合格时，买方可以采取哪些措施？”工具描述从“合同能够回答哪些问题”解释用途，不要求模型了解向量实现。

引用可以来自图像检索或此前的问题检索。不存在、跨会话或已驱逐引用直接报错，不调用 Embedding 或退回全库；查询期间引用失效也不发布派生结果。范围读取不推进旧结果分页游标。新查询只按本次问题相似度排序，暂不融合历史分数，也不覆盖旧结果。

非空成功返回 `status=success`、新 `result_id`、`count` 和查看提示，供内部 Agent 继续限定查询；不提供 view 工具。零结果成功返回 `count=0` 和未找到提示，不生成 ID、不占用 LRU。执行失败返回明确错误，不伪装成空结果。

## 编码与 ES 查询

实现位于 `agent_core/subgraph/contract_retrieval/tool/contract_question_search.py`。查询调用 `render_user_query_embedding_input()`，与入库问题编码共用 `contract-question-retrieval-en-v1` 成对指令中的 `USER_QUERY_EMBEDDING_INSTRUCTION`。只对问题编码一次，不重写后另行生成问题列表；使用既有 ChatML 边界、Embedding 客户端、模型配置和全局并发限制。

校验响应模型、数量、维度、有限值与非零范数后，执行 L2 归一化。查询 ES `vectors.question_fusion`，范围 ID 放入 kNN 的预过滤条件；另检查返回项仍在范围内，按 SQLite `ready` 状态过滤、去重并稳定排序。分数由 cosine mapping 的 `_score` 转换为原始余弦值。

预取最多配置数量的四倍（上限 200），最终最多返回配置数量。结果属于有限近邻候选，不保证全量；状态过滤后可能不足配置数量。超时或分片失败作为执行错误。模型更换后需保证查询模型与已有 ES 向量兼容，本工具不会重算历史向量。

## 配置与结果展示

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `COMMUNICATION_CONTRACT_QUESTION_SEARCH_TOP_K` | 10 | 最多返回合同数，范围 1–50。 |
| `COMMUNICATION_CONTRACT_QUESTION_SEARCH_MINIMUM_SIMILARITY` | 留空 | 原始余弦下限，范围 -1 至 1；留空不设门槛。 |

这两个配置不暴露为模型参数。结果池容量和每页大小复用既有 `COMMUNICATION_CONTRACT_SEARCH_*` 配置。搜索 SSE 为 `local-search`，查看与翻页为 `thinking`。

结果池仅保存候选 ID、分数和查询方式。内部调用只返回数量及引用；子 Agent 提交最终集合后，由程序回读合同名称与摘要。详情见[子图契约](contract-retrieval.md)。

## 历史验证与当前迁移

以下实验记录属于工具独立注册阶段；当前入口与结果展示以[候选子图](contract-retrieval.md)为准。

43 项离线回归通过，包括配对指令、向量归一化及非法响应、只暴露两个参数、配置边界、全库查询、图像结果限定问题查询、引用失效、空结果不入池、旧结果不覆盖、类型对应的渲染，以及“图片检索 → 问题检索 → 分页查看 → 最终回复”的正式主循环链路。

离线测试使用模拟模型和 ES 响应。另已完成八份 mock 合同、真实 Embedding、独立 ES 索引和真实主模型的联调：六条标注查询均首位命中，普通查询分页、限定范围及零结果三个任务全部完成，工作区写入成功。一次模型协议错误自行恢复；无门槛时仍会返回弱相关尾部候选，小样本结果不代表生产精度。详见[实验分析](../../../../experiment/contract-question-search-live/output/20260918T104355.902427Z/analysis.md)。实验索引已清理，未修改正式合同数据。后端加载最新代码后生效。
