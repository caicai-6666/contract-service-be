# 按合同摘要检索

`search_contracts_by_summary` 适用于已经知道目标合同大致主题或具体内容，希望据此寻找合同的场景。调用模型应将已有线索整理成一段简短、稍正式的拟写合同摘要，使用陈述句描述主题、交易标的、用途及已知关键约定。现作为[合同候选查询子图](contract-retrieval.md)内部工具，不直接向主模型注册。不依赖 ES；合同名称仅用于结果展示，不参与本工具编码或全文检索。

---

## 工具契约

| 参数 | 必填 | 含义 |
| --- | --- | --- |
| `query` | 是 | 1–10000 字符的拟写合同摘要，例如“本合同涉及生产设备采购，约定设备验收、验收后尾款支付及质量保证安排。”。 |
| `result_id` | 否 | 本次子图调用的内部结果集完整引用；省略或 null 使用宿主限定的初始范围，未限定时查询全部 ready 合同，传入则限制在该集合内。 |

拟写摘要仅用于检索，不是已核实的合同内容；只整理已有线索，未知的主体、金额、日期、期限、责任与条款直接省略，不为使摘要完整而补造。不直接照抄“帮我找……”式请求或写成待解答的问题。仅知道想解答什么业务问题时，可使用问题检索工具。该表达方式旨在贴近存储摘要，是否改善召回仍需实验验证。成功返回有限候选的结果集 ID 和数量，供子 Agent 继续查询或收束；零结果不生成引用。过期范围报错，不退回全库。查询期间会话释放或原引用驱逐，不发布派生结果。失败不能解释为没有相关合同。

---

## 检索与排序

查询复用 `contract-summary-v1` 摘要编码指令，返回独立 L2 归一化向量。SQLite 同一读取快照内执行 BM25 和余弦向量两路召回，范围及 ready 状态在两路截断前过滤。全文检索使用 Lindera（Jieba），输入先切词，再引用转义构造 OR 查询，不将自然语言作为 FTS 运算符执行。

每路最多召回 `min(top_k × 4, 200)` 份合同，等权 RRF 计分 `sum(1 / (60 + rank))`，rank 从 1 开始；某路未命中贡献为零，不调整分母。按 RRF 降序、document_id 升序稳定排序后截断 top_k，不融合源结果集的旧分数。

旧摘要没有向量或模型、版本、维度不兼容时仍参与 BM25。向量为精确扫描且未设置相似度门槛，可能包含弱相关尾部候选；RRF 不是概率或余弦值，候选数量不是满足业务条件的全库总数。摘要可能省略细节，需要打开原文核实具体约定。

## 索引与分页

`contract_summaries_fts` 是以 `contracts.rowid` 关联的外部内容索引，只索引 summary。初始化首次回填历史摘要，重复初始化不重建；插入、更新摘要、删除合同通过触发器在同一事务同步。使用元数据存储连接或加载相同扩展的连接执行数据库维护，不能用未加载 Lindera 的连接写入。

内部结果池只驻留 ID、分数和查询方式，查询后只回显引用与数量，不提供 view 工具。最终名单由程序读取，详见[合同候选查询子图](contract-retrieval.md)。

## 配置与验证

`COMMUNICATION_CONTRACT_SUMMARY_SEARCH_TOP_K` 默认 10，范围 1–50；分页大小和驻留容量沿用 `COMMUNICATION_CONTRACT_SEARCH_*`。摘要模型与编码契约见[摘要向量存储](../../data/contract-sqlite-metadata.md#合同摘要向量)。

实现位于 `agent_core/subgraph/contract_retrieval/tool/contract_summary_search.py`、`app/infrastructure/contract_summary_search.py`。测试采用真实临时 SQLite、Lindera 和 sqlite-vec，覆盖融合、单路命中、范围限制、旧数据回填、增删更新、非法引用、空结果和页面标签；正式循环测试模拟生成与编码，验证搜索→查看→最终回复。本轮不据此宣称真实模型召回质量。
