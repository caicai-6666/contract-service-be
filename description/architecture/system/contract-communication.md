# Communication 总体设计

> **设计记录：** 本文记录截至 2026-09-08 已确认的需求与待定边界。当前实现以“实现现状与验证”章节为准；未实现设计不代表当前接口行为。

---

## 定位与核心结构

Communication 面向非专业用户，连接自然语言诉求与系统合同能力。用户不需要理解索引、字段代码或工具细节；助手负责理解目标、组织工作，并提供可核对的结果。

已确认采用“业务门禁 + Agent 骨架 + 可扩展工具”的结构，不为每项能力单独建设顶层流程：

| 部分 | 职责 |
| --- | --- |
| 业务门禁 `business_gate` | 判断问题相关性、检查 PDF 并形成准入或等待用户确认的结果。 |
| 智能体骨架 `agent_core` | 管理记忆，规划和拆解任务，持续推进目标，调度合同查询等工具。 |
| 确定性程序工具 | 查询、计算、统计等有明确程序执行规则的操作。 |
| 专用子智能体工具 | 合同对比、联网分析等专一任务；向主助手返回结果供统一组织。 |

主助手具有任务拆解与长期规划能力，不等同于固定工作流，也不预设多个同级助手共同管理用户目标。当前不选择记忆存储、工具协议或调度实现。

首批范围是业务门禁和骨架；计算统计、联网、专项分析等能力逐步以工具扩展。合同查询属于骨架必须能够调度的基础能力，不要求将具体查询实现固化在骨架内部。

## 用户、会话与轮次

已实现统一内存层保存按轮次组织的关键轨迹，并在终态后台备份至 SQLite。方法调用、阶段说明与最终答复按统一顺序交错记录，具体规则见[轮次有序轨迹设计](../workflow/contract-communication/turn-trace.md)；该存储与运行时已接通，不等同于有界 SSE 缓存或展示快照。
已确认以用户为单位管理对话，并以 `conversation_id` 标识会话、`turn_id` 标识轮次。一次提交可包含文字、PDF 列表或两者；一次轮次组织对应的门禁、执行、输出和用户控制。

对话归属隔离与合同可见范围是不同问题：不能因为用户有权查看合同，就允许其读取其他用户的对话。现有合同权限仍然适用，业务门禁和模型不能替代程序侧权限检查。

会话与轮次标识均由服务端创建，已提供会话列表、改名、删除、打开和向前刷新接口。事件层限制同一会话只保留一个非终态轮次；待激活或处理中的调整必须显式替代旧轮次。已接通 HTTP 创建、替换与取消，不代表已有完整历史管理。

## 输入与任务推进

已确认的业务顺序如下：

1. 文字和文件均为空时，不启动任务，提示用户提供输入。
2. 有文字时判断是否与合同或业务问题相关；无文字则跳过此步。
3. 有 PDF 时独立检查各文件；无文件则跳过文件检查。
4. 问题不相关时提示并终止；出现文件剔除时以本轮最终答复请求确认，结束本轮，用户在下一轮回复。
5. 没有文件被剔除时进入 `agent_core`，包括仅上传文件且文件通过检查的情况，不强制先补文字。
6. 骨架根据目标组织后续工作，通过事件和文本增量与用户交互。

门禁判断、逐文件结果和确认分支的权威说明见[业务门禁子图](../workflow/contract-communication/business-gate.md)，此处不规定具体模型提示词和节点算法。

## 交互与控制

已确认将提交、事件订阅、快照和主动取消分为四个接口，精确路径、占位响应及后续协议讨论见[多轮对话 API](../../api/communication.md)。用户需要同时接收 SSE 处理事件和回答文本增量。

已确认每次用户输入对应一个轮次，轮次给出本次最终答复后结束事件流。消息区分 `intermediate` 阶段提示与 `final` 本轮交付；澄清和确认问题也属于 `final`，不要求输出必须是总结。`completed` 只表示本轮交付完成，不表示整体业务目标已经达成。

用户回答、补充或调整方向时，在同一会话下提交新轮次，不使用 `awaiting_confirmation` 保持旧连接。创建仅暂存输入与注册，首次有效订阅才激活，期限为 180 秒；超时清理输入并拒绝激活。已接通新轮次提交，但上下文继承与工作流执行仍待实现。

主动取消后的模型上下文保留用户问题及“已终止”标记，不保留本轮半成品。用户补充信息或调整方向不是取消整个目标，模型应依据最新要求更新工作。完整语义由[用户消息与上下文设计](../workflow/contract-communication/user-context.md)维护。

SSE 断线不应被解释为用户主动终止。执行期间补充或调整要求时，旧轮次进入 `superseded`，关联同会话的新轮次并关闭旧流；已完成轮次则保留原终态，不改写为取消或被替代。内部事件注册已提供原子切换与迟到事件隔离；真实旧执行中断、新执行启动、文件材料关联及上下文继承仍待实现。

## 待逐步明确的事项

- “业务问题”的具体相关性边界，以及无法可靠判断时的处理方式。
- 历史管理、新轮次与前轮确认材料和上下文的关联契约。
- 文件限制、模型识别范围、无法判定时的反馈及临时文件生命周期。
- 长期规划的恢复机制、记忆保留策略；是否包含离线主动执行和定时提醒尚未确定。
- SSE 已有事件负载、快照和有限回放；待补任务提交幂等、取消实际执行的并发保证与跨进程持久化。
- 用户消息意图的数据结构及其与实际任务状态的映射。

后续设计应在对应主文档中逐步补充；只有需求明确后才升级为正式契约，只有代码及验证完成后才标记为已实现。
