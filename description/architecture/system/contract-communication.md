# Communication 总体设计

> **当前实现：** 用户问答采用完整业务门禁、共享 Agent Core 与 exploration 交付模式；可选 A2A 模式通过独立 worker 处理跨平台任务。本文说明模块关系，接口与精确数据契约由下述专题维护。

---

## 定位与核心结构

Communication 将用户的自然语言诉求连接到合同检索、原文查看和分析工具。用户无需理解字段代码或工具协议；程序负责权限、校验、预算与生命周期，模型负责理解任务、组织探索并提供有依据的回答。

| 模块 | 主要职责 |
| --- | --- |
| `business_gate` | 用户输入的 PDF 可读性、命名与摘要、主题冲突和四维相关性判断，统一形成准入或拒绝。 |
| `agent_core` | 模式无关的模型循环、工具执行、上下文预算、工作区管理、FIFO 摘要、有限纠错和私有审计。 |
| `exploration` | 用户 SSE、中途及最终输出、沟通提醒和驻留历史适配。 |
| `a2a` | 首次受理、跨平台任务执行、内存响应链接续和文件可见范围过滤；传输由独立 worker 负责。 |
| 确定性工具与专用子图 | 合同候选查询、图像和关系检索、文件及网页阅读、记忆检索、日期计算、统计和外部专家求助。 |

主助手自行规划与推进任务，不依赖一个独立的规划工具。工具通过统一注册表同时提供模型 Schema、参数解析和执行绑定；模型动作经完整校验后才提交成功状态。模式、工具和工作流入口见[合同沟通智能体](../workflow/contract-communication/readme.md)与[Exploration 与 A2A 划分](../workflow/contract-communication/agent-modes.md)。

## 用户、会话与轮次

用户通过中间件登录及平台管理员资格验证后访问 HTTP/SSE；会话、附件和轮次按稳定 userid 隔离，用户名与部门仅作资料。共享正式合同的 HTTP 访问与 A2A 的文件等级过滤是不同边界，详见[用户身份与所有权](../data/user-identity.md)和[A2A 运行时](../workflow/contract-communication/a2a-runtime.md)。

会话由 `conversation_id` 标识，每次输入建立新的 `turn_id`。已实现会话列表、改名、删除、打开与向前刷新；同一会话最多存在一个非终态轮次。任务轨迹和工作区统一驻留，终态后台备份至 SQLite；用户展示事件与模型原生交互分开保存，不能用有界 SSE 缓存重建完整历史。见[历史驻留与备份](communication-history.md)。

## 用户问答处理流程

1. 创建请求仅暂存文字、引用合同和 PDF，首次有效 SSE 订阅在 180 秒内激活；超时释放输入，不执行模型。
2. 门禁检查文件可打开及视觉可读，逐文件生成名称和摘要；发现独立无关内容时经主题冲突节点拒绝。
3. 文字、文件、文件与文字、历史上下文四个相关性维度按适用条件判断并加权聚合；阈值和失败分流以[业务门禁](../workflow/contract-communication/business-gate.md)为准。
4. 所有未放行出口统一进入拒绝回复，形成 rejected 终态，附件不写入业务 upload 目录。回复生成故障仍提供兜底反馈。
5. 完整放行后批准附件准入，记录摘要和页数，装配最新工作区、最新累计摘要及其后的有效任务和当前输入，进入 exploration 与共享 Core。
6. 模型逐轮调用一个工具，中途输出后继续，最终通过 finish_task 结束本轮；成功交互写入原生轨迹，失败链仅临时用于纠错并保留私有审计。
7. 终态冻结后后台备份轨迹、工作区和已准入附件；记忆归档服务独立加工三入口检索投影并安全驱逐空闲会话。

门禁只读取最新摘要后最多五轮有效历史；Core 读取该摘要后的全部有效任务，另受预算约束。向前 refresh 扩展用户可见历史，不扩大 Core 的摘要边界。上下文、FIFO 和资源释放分别见[上下文装配](../workflow/contract-communication/context-assembly.md)、[主助手生成循环](../workflow/contract-communication/agent-runtime.md)和[页面资源管理](../workflow/contract-communication/page-content-management.md)。

## 交互与控制

每轮通过 SSE 交错发送状态、工具进度和回答增量；消息区分 intermediate 与 final，最终澄清或确认问题也可以结束本轮。completed 表示本轮交付完成，不等于用户的整体目标已达成。精确方法、字段和恢复顺序见[多轮对话 API](../../api/communication.md)。

待激活与完整门禁期间 `can_interrupt=false`，用户取消或显式替代返回 409，旧任务保持执行。完整门禁通过并进入 Core 后允许取消或替代；取消旧生产协程、拒收迟到结果，并同步冻结历史和 SSE。SSE 断线不等于取消，会话删除及系统关闭不受用户中断限制。新轮次读取旧任务的真实状态和已接受交互，不把中断正文当成正式结论。详见[用户消息与上下文](../workflow/contract-communication/user-context.md)。

## 持久化与运行边界

- 轨迹和工作区使用同一份驻留状态，按版本和锁协议提交；累计摘要按被压缩完整前缀插入，备份事务同时保存排序、摘要、任务和工作区。
- 原生思考随已接受的 assistant 消息保存、备份和恢复，不再配置独立思考窗口；失败轨迹、普通附文及私有审计不进入权威工作区。
- 会话记忆采用用户输入、中途输出、最终输出三入口检索投影；归档与原始备份分开调度，不能将已备份视为已加工。见[归档服务](communication-archive.md)。
- 正式后端保持单 worker。重启可恢复已备份轨迹和工作区，不自动续跑活动任务；A2A 响应链和实时事件不持久化。

## 验证与剩余边界

现有专题记录了门禁、真实共享循环、上下文过滤、工具执行、预算、取消/替代及 SQLite 备份的离线回归，以及部分真实服务实验。历史实验记录不等于本次已重新执行；模型判断质量、长会话性能和实际外部服务可用性须按对应场景验收。

当前未提供任务提交幂等键、跨进程实时恢复、会话总驻留内存预算、附件孤立文件回收或通用临时表格查询。离线主动执行、定时提醒及长期目标自动恢复尚无正式契约；不得将这些能力视为现有接口行为。
