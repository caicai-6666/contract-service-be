# Communication 记忆归档与空闲驱逐

> **实现状态：** 已接通外层确定性筛选、单任务子图并发加工、三入口检索投影原子提交及空闲安全驱逐。正式应用启动扫描。原始任务/工作区备份独立运行，不等待向量计算；存储契约见[Communication SQLite存储](../data/communication-sqlite.md)。

## 职责与入口

`CommunicationArchiveService` 已接入正式应用生命周期，以会话为单位协调扫描、分批、调用 [conversation_memory](../workflow/conversation-memory/readme.md)、检索数据入库和安全驱逐。它不生成工作区、不改变原任务状态、不创建上下文截断摘要，也不提供查询接口。

原始轨迹与工作区继续使用[历史服务的后台备份](communication-history.md)，不必等待模型。归档加工独立进行：已经备份的原轨迹仍可能需要筛选、格式化和向量化。这两个完成状态不能混为一谈。

## 扫描与分批规则

正式应用默认使用以下参数，位于 `CommunicationArchiveService` 构造器；测试可以注入短时间与单调时钟，当前不增加环境变量配置。

| 参数 | 默认值 | 行为 |
| --- | --- | --- |
| `scan_interval_seconds` | 600 秒 | 启动后每十分钟扫描当前驻留会话。 |
| `minimum_batch_size` | 10 条任务 | 不把摘要算作任务。 |
| `idle_scan_limit` | 3 次 | 连续三个有效扫描周期没有活动。 |
| `idle_seconds` | 1800 秒 | 同时满足至少三十分钟实际空闲。 |
| `processing_timeout_seconds` | 600 秒 | 整批并发加工超时后取消并保留待处理状态。 |
| `task_concurrency` | settings.embedding.max_concurrent_requests | 同批单任务图最大并发数，构造器可单独指定正整数；实际模型请求仍受全局Embedding配额限制。 |

普通批次从最早未加工任务开始，至少包含十条；第十条不是 `completed` 时，继续包含至遇到的第一条 `completed`。有更多任务则按相同规则继续分批，不足十条或找不到完成结尾的尾部留待下次。任务状态为 `failed` 也可以加工，这与记忆加工本身失败是两回事。

即将驱逐时强制处理剩余尾部：即使不足十条，或者最终状态为取消、调整、失败、过期，也允许作为最后一个批次；绝不包含尚未终止的任务。普通批次仍保留完成结尾要求。

任务按原 `sequence` 排序，不按 UUID 排序。读到活动任务即停止，不跳过它处理更晚任务。扫描先捕获范围，加工时不混入扫描之后的新任务。

每个会话至多一个在途作业。扫描只派发作业，不等待模型；跨会话批次串行，同批任务通过有界Semaphore并发；单任务内部各入口和中途各条输出仍可并发编码。单会话失败不阻止其他会话继续处理。

## 状态、重启与数据契约

| 状态 | 权威标记 | 含义 |
| --- | --- | --- |
| 原始轨迹已备份 | 驻留层 `_persisted` / SQLite 原记录 | 原问题、附件引用、完整公开轨迹与原计时已有副本。 |
| 记忆加工完成 | `conversation_records.memory_processed_at` 非空 | 已经完成筛选及所需三入口编码，结果已提交。 |
| 无需向量化但已加工 | 标记非空，检索字段均空 | 外层筛选跳过或三个区域均无内容的任务，不再重复调用模型。 |
| 尚未加工或加工失败 | 标记为空 | 保留原轨迹，后续扫描继续尝试。 |

加工标记位于原任务表，三组文本/向量位于独立conversation_task_retrievals。旧综合检索字段在初始化迁移时移除，旧加工标记清空，重新走本流程；新表数据在重复初始化时保留。跳过任务写入全NULL投影及完成标记，不因没有向量而永久重试。加工标记和检索投影不进入前端轨迹响应。

打开会话仍只驻留最新摘要及后续历史。归档会按需补读该会话 SQLite 中尚未加工的更早任务，避免旧任务因摘要窗口截断而永远漏掉；此补读不扩展前端或问答模型的历史窗口，不读取已存的向量与检索正文。未驻留的会话不会被后台主动打开，重启后尚未加工任务在会话再次打开后恢复调度。

Service向单任务图传入完整ConversationHistoryRecord副本，保留record_id、sequence、turn_id、状态、payload和计时，但不传用户密钥或工作区。图只把三个公开区域送入Embedding，身份和序号由程序持有。输出record必须与该输入完整相等，retrieval.record_id必须一致，禁止错配、修改原文或遗漏任务。

外层 `should_index_task` 的确定性筛选规则：

- 仅接受kind=task且status为终态；活动任务已在历史候选阶段阻断。
- rejected、expired不进入图；payload.agent_core_ready明确为False时也跳过。
- completed、cancelled、superseded、failed可以加工，失败终态不等于没有可保留交互。
- 没有agent_core_ready的旧任务保持兼容，不凭字段缺失推断门禁拒绝。
- 跳过任务直接构造与原record_id关联的空检索投影，随同批提交；不调用MLLM进行“价值筛选”。无正文区域由单任务图跳过编码。

筛选在分批之后逐任务执行，因此跳过任务仍参与归档批次范围与完成标记管理，不会成为驱逐时的永久待处理项。

## 提交与失败边界

1. 在锁外执行外层筛选，按任务并发调用单任务图完成格式化及向量化。
2. 完整校验图输出、任务覆盖及顺序；本批任何加工失败则本批不提交，保留原批次在下一扫描重试。子图失败不返回待入库半成品；Service等待本批所有作业清理，按原顺序收集后统一提交。此前已成功提交的批次不受影响。
3. 先确认原始备份回执，再在驻留锁内复制最新工作区及其已落库版本。模型加工期间的新工作区可以进入此次快照，但不重新解释其内容。
4. 校验任务引用的 upload 文件。只有 accepted 附件及旧版已注册附件需要文件校验；pending/unavailable 不能通过归档补写文件，也不因缺失而阻止归档。已准入文件在原始备份时保存，其字节暂留驻留会话，可恢复缺失文件并校验内容；重启后的老文件只验证存在、可读和非空，缺失则阻止归档，不伪造内容。路径必须为已注册 UUID PDF，拒绝越界路径和符号链接。完整规则见[附件准入与延迟落盘](communication-history.md#附件准入与延迟落盘)。
5. `archive_tasks_with_workspace` 在同一 SQLite 事务提交原轨迹、三组检索文本、对应float32向量BLOB、加工完成时间和工作区。向量继续执行固定 4096 维、有限且 L2 归一化校验，原payload不被检索投影替换。编码期间若FIFO摘要插入改变sequence，存储层按record_id采用当前已落盘序号，其余字段仍完整校验，禁止旧序号覆盖新顺序。
6. 事务成功后才确认内存持久化状态，并释放本批附件的暂留字节。磁盘文件及驻留原轨迹继续保留。

数据库事务、文件验证或模型调用失败均不允许驱逐。已完成的此前批次不撤销；失败批次下次重试。数据库提交成功但回执丢失时，下一次读取持久化加工标记跳过已完成批次，不重复模型加工；存储接口也支持相同结果幂等确认，拒绝覆盖不同的已加工结果。

原始备份、归档提交、删除和驱逐共用备份协调锁；模型调用期间不持有它，也不持有驻留锁。删除后迟到结果不能重新创建会话；同 ID 的新驻留实例也不能接收旧实例的归档结果。

## 驱逐信号与最终检查

每个驻留会话有 `residency_id`、`activity_generation`、最后活动时间和连续空闲扫描次数。注册新任务、任务进入终态、工作区更新、用户打开或向前刷新会话都会更新活动信号并重置空闲计数。待激活或处理中的任务阻止空闲计数。重复调用扫描接口不等于经过多个十分钟周期。

驱逐作业捕获实例 ID 与活动代数。所有加工、文件检查和落库结束后，最终在同一驻留锁内比较并删除，必须同时满足：

- 仍是原驻留实例，活动代数未改变。
- 没有活动任务、未备份轨迹或未确认的备份副本。
- 数据库没有该会话尚未加工的任务，当前驻留任务全部具有加工完成标记。
- 内存最新工作区已同步落库。
- 当前驻留轨迹引用的附件通过检查。

加工期间来了新输入时，只取消本次最终驱逐，已成功归档的旧批次仍保留；不将新轨迹误标为已处理，也不覆盖新工作区。即使新输入恰好在最后文件检查期间到达，锁内比较仍能保护它。

驱逐只释放内存的历史、工作区、附件字节和该会话事件运行时，不删除 SQLite 行或 upload 文件。之后通过 open 从 SQLite 恢复历史与工作区，实时 SSE 事件源不重建。

## 真实Embedding链路验证

已运行独立[归档链路实验](../../../experiment/memory-persistence-live/README.md)：12任务经正式筛选、单任务图和真实Embedding处理，成功保存12条检索记录，其中3条筛选跳过、9条含向量，共22个区域向量。主动注入SQLite失败后整批回滚，重试成功；强制尾批完成后安全驱逐，新建历史服务恢复工作区/窗口且不重复编码。具体产物与边界见[实验分析](../../../experiment/memory-persistence-live/output/20260916T054858.732596Z/analysis.md)。本次不调用MLLM，不操作生产库。
